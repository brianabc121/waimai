# 地址库 设计方案（2026-11-23）

brian 的要求：平台后台新增地址管理页，按国家 / 省份 / 地区管理详细地址；代客下单填的地址格式化后和地址库比对（限定地区），不重复就存进去；代客下单输入地址时先推荐地址库里的地址，下拉最下面有“更多”，移到“更多”上才加载谷歌推荐；地址要有经纬度，“查看”按钮直接拼 URL 打开谷歌地图；陌生地址用“打开谷歌地图”弹窗搜索或手动选点拿经纬度。

截图在项目文件 `address-book-screens/`：ab1 “更多”加载谷歌推荐，ab2 下一单先推荐地址库，ab3 后台地址库，ab4 写法不同的重复地址被拒，ab5 后台手机版。

## 1. 调研：用 Elasticsearch 还是 PostgreSQL

结论：**用现有的 PostgreSQL（pg_trgm 扩展）**，不加 Elasticsearch。

| | PostgreSQL + pg_trgm | Elasticsearch |
|---|---|---|
| 部署 | 不加任何服务。pg_trgm 是 PostgreSQL 自带扩展，PG13 起是“受信任扩展”，库的所有者就能装；主流托管库（RDS、Cloud SQL、Supabase 等）都支持 | 多一个服务（至少 1–2 GB 内存），要备份、升级、监控 |
| 数据一致 | 地址和订单在同一个事务里写入，不会“订单有了、地址库没有” | 要另外同步（双写或订阅变更），会有延迟和漏同步 |
| 规模 | 地址按地区查，一个地区几万到几十万条，GIN 三元组索引毫秒级 | 千万级以上、需要复杂打分时才有优势 |
| 匹配能力 | 子串（任意位置）、词序不限、错字（三元组相似度）、中文泰文缅文都能用 | 分词、同义词、拼音更强，但中文要另装分词插件 |
| 去重 | 唯一索引直接保证“同一地区同一地址只有一条” | 本身不保证唯一，还得靠数据库 |

外卖的地址量远没到要 ES 的程度，而且去重必须靠数据库的唯一约束。以后真需要拼音或同义词，可以再在 PostgreSQL 里加字段，或者那时再接 ES，地址库的表不用改。

## 2. 数据

表 `address_book`（迁移 00051）：

- 地区：`country_code`、`country`、`province`、`city`，取**下单门店**的地区（门店在配送地图页定位时由谷歌反查得到，英文名）。门店还没有地区的，地址记在“未知”地区下。
- `line`：格式化后的地址（全角转半角 NFKC、多余空格合并、逗号前不留空格、去掉结尾的标点）。
- `line_key`：比对用的键，由数据库函数 `addr_key()` 算出：NFKC、小写、去掉所有空格和标点。“Ayala Tower One, 6750 Ayala Ave.” 和 “ayala tower one，６７５０ ayala ave” 是同一个键。
- `lat`、`lng`：必填。没有经纬度的地址不进地址库。
- `source`：`staff`（代客下单）、`admin`（后台添加）、`import`（上线前的历史代客单和会员地址，迁移时一次导入）。
- `branch_id`：第一次是哪家店送的；`uses` 使用次数；`last_used_at`。
- 唯一索引 `(country_code, province, city, line_key)`，三元组 GIN 索引在 `line_key` 上。

## 3. 入库（要求 1）

代客下单成功时（配送单、有经纬度），在同一个事务里：按门店地区和 `line_key` 查重，没有就存入，有就使用次数加一（不改已有的经纬度，后台改过的以后台为准）。

## 4. 下拉推荐（要求 2）

输入地址时下拉的顺序：

1. **这个号码用过的地址**（最多 4 条）
2. **地址库**：门店所在地区里匹配的，最多 6 条。匹配规则：输入的每个词都出现在地址里（词序不限，空格标点忽略）；或者三元组相似度够高（容错打错字）。排序：开头就匹配的优先，再按相似度、使用次数、最近使用。
3. **本店送过的地址**：以前没有定位、不在地址库里的，补在后面。
4. **更多…**：前面三类有结果时，只有光标（鼠标移上去，或者用 ↑↓ 键走到这一行）到了这里，才去请求谷歌推荐，并把结果列在下面。**前面三类一条都没有时（2026-11-28 brian 要求），不用店员触发，停止打字约 0.6 秒后自动请求谷歌推荐**；为了少花调用费，至少输入 3 个字才自动请求，已经定位过的地址不再请求。每改一次输入就清掉，再到“更多”上才重新请求，这样不会每打一个字就花一次谷歌调用费。谷歌推荐用门店所在国家限定、门店位置优先；选中后再取经纬度（Places API (New)；没开 Places 时退回地理编码搜索）。

下拉支持 ↑↓ 选择、回车选中、Esc 关闭。每条有经纬度的推荐旁边有“查看”。

## 5. 查看（要求 3）

代客下单页地址按钮行新增“🔍 查看”：有经纬度时直接打开 `https://www.google.com/maps/search/?api=1&query=纬度,经度`（新窗口，不调 API）；没有经纬度时按钮变灰。后台地址库每行也有“查看”。

## 6. 陌生地址（要求 4）

已有的“📍 打开谷歌地图”弹窗：可以搜索，也可以拖动地图手动选点，点“完成”后经纬度写到这个地址上，店员输入的地址文字保留不变。下单后它也会进地址库。

## 7. 后台地址库页面 `/admin/addresses`

- 左边按 国家 → 省份 → 地区 逐级筛选，带数量；有门店但还没地址的地区也列出来（数量 0）。
- 搜索（同样词序不限、可有错字）、按来源筛选、排序（最近使用、使用次数、最新加入、按地址）。
- 每行：详细地址、国家/省份/地区（没选到具体地区时显示）、经纬度、来源和门店、使用次数、最近使用、查看 / 修改 / 删除。
- 新增和修改：选已有地区或手填，经纬度可粘贴“纬度, 经度”或在地图上选（新增时没选地区就用地图点所在的地区）。同一地区里写法相同的地址会提示“这个地区已经有这个地址了”。
- 新增、修改、删除都记在操作记录里（`address.create` / `address.update` / `address.delete`）。删除不影响已下的订单。

## 8. 我定的取舍（可以改）

- 地区用**门店**的地区，不对每个地址再调一次谷歌反查，省调用费。门店在两个城市交界、送到隔壁城市的地址，会记在门店所在城市下。
- 只记代客下单（要求里说的），顾客自己下的单不进地址库。
- 地址库是全平台共用的：同一地区的不同商家互相能看到推荐（只有地址文字和位置，不带顾客信息）。

## 11. 顾客端和代客下单共用一个地址推荐模块（2026-11-28 补充）

brian 要求：顾客端地址推荐和代客下单地址推荐合并在同一个服务模块，统一优先使用系统地址库里的地址。

**同一条规则**：先查我们自己的地址；有匹配就只显示这些，要看谷歌的再点“更多”；一条都没有才自动问谷歌。

**后端一个模块** `internal/app/address_suggest.go`，入口 `SuggestAddresses(AddressAsk)`：

| 谁在问 | 接口 | 查什么 | 返回什么 |
|---|---|---|---|
| 店员（代客下单） | `GET /merchant/branches/:bid/address-hints`（要登录和权限） | 本号码用过的、地址库（门店所在地区）、本店送过的 | 整行地址、房号、备注、配送区和配送费 |
| 顾客（地图选点） | `GET /address-suggest?q=&slug=` 或 `&lat=&lng=`（公开，限流） | 只查地址库里**可公开**的地点 | 只有地点名、街道地址、坐标 |

**前端一个模块** `web/src/addressSuggest.ts`：`ownAddresses()` 按身份调上面两个接口，`googleNext()` 决定要不要自动问谷歌，`hintPlace()` 把我们的地址显示成和谷歌推荐一样的“地点名 + 街道”。代客下单页（`ManualOrderView.vue`）和顾客地图选点（`PlacePicker.vue`，新增地址、商城定位、入驻申请都用它）都走这个模块。

**顾客隐私**（我定的，可以改）：

- 顾客端只显示地址库里“可公开”的条目：谷歌认识的地点（有 `place_id`），或平台后台自己录入、导入的（来源是 admin / import）。店员手打的一行地址（可能写着某家的门牌、房号）只给店员看，不给顾客。
- 顾客端永远拿不到房号、送达备注、电话、谁用过这个地址，也不返回配送区和配送费（顾客端不出现配送区的规则不变）。
- 至少输入 2 个字才查；有店铺时按店铺所在地区查，没有店铺（商城定位、入驻申请）时按地图中心周围约 55 公里查。
- 输入的是经纬度时不查地址库，直接定位。

**没做**：顾客自己在地图上选的地点不写进地址库（地址库仍只收店员代客下单用过的和后台录入的）。

**测试**：Go `TestPublicAddressSuggest`（店员看到 3 条、顾客只看到 2 条公开的，不带房号备注配送区；带店员参数但没有店员身份也只按顾客处理）；`e2e/placename.cjs` 第 2b 段（顾客输入 trump tower 先出地址库的地点且没问谷歌、返回内容里没有房号电话、“更多”才问谷歌且不重复、地址库没有时直接问谷歌）。
