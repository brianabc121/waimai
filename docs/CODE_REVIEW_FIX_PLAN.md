### 1.1 H01 未收足款的订单可按整单退款（确认 + 实跑）

- 位置：`internal/app/fulfil.go:575–651`（`RiderDeliverPaid`），`internal/app/voids.go:647–924`（`Refund`）。
- 调用链：骑手送达 → `RiderDeliverPaid` 只要求 `collected >= 0`；`collected != due` 时订单变成 `fulfillment_status='delivered'`、`payment_status='unpaid'`（`fulfil.go:626–631`）。之后 `Refund` 只检查“已接单 + 已送达/已取/已结账”（`voids.go:700–703`），可退额度 `q.Left = o.Total - paidBack`（`voids.go:780`），全程没看 `payment_status` 和实收。
- 实跑：外卖一杯茶应付 161.34，骑手填收到 0，订单 `unpaid` + `delivered`；店原因退这杯茶，**成功退现金 161.34**。
- 触发条件：外卖货到付款，骑手少收、没收或多收（多收也停在“未付”）；自取和堂食在取餐/结账时一律记已付，不受影响。需要有售后权限的店员操作。
- 影响：没收到的钱被当现金退出去，或变成顾客可花的店铺余额（凭空多出余额）。
- 顺带发现：少收的单一直是“未付”，不进对账的营业额（见 M04）。

### 1.2 H07 分次按菜退款金额不对（确认 + 实跑，**现有算法错误**）

- 位置：`internal/app/voids.go:717–787`，`internal/app/money.go:529`（`without`）。
- 原因：之前退过的菜只用来校验“还能退几份”（`voids.go:762`）。算钱时 `m.without(less)` 只从**原订单**里去掉**本次**的菜（`voids.go:773`），建议金额 = 原应付 − “原订单去掉本次的菜”的价（`voids.go:781`）。之前退掉的菜还被当成在单上，所以每次都按“第一次退”来算。
- 手算（自取，3 瓶水每瓶 30.00，服务费 5%，包装费 10.00，税 12% 外加；和测试门店的设置一样）：

  | | 菜 | 优惠 | 服务费 | 包装 | 税 | 应付 |
  |---|---|---|---|---|---|---|
  | 3 瓶，第二份半价（或满 90 减 15） | 90.00 | −15.00 | 3.75 | 10.00 | 10.65 | **99.40** |
  | 2 瓶，第二份半价 | 60.00 | −15.00 | 2.25 | 10.00 | 6.87 | 64.12 |
  | 2 瓶，没有活动 | 60.00 | 0 | 3.00 | 10.00 | 8.76 | 81.76 |
  | 1 瓶 | 30.00 | 0 | 1.50 | 10.00 | 4.98 | 46.48 |

  - **第二份半价**：一次退 2 瓶应退 99.40 − 46.48 = **52.92**。分两次各退 1 瓶，程序两次都给 99.40 − 64.12 = 35.28，合计 **70.56，多退 17.64**。
  - **满 90 减 15，顾客原因**：一次退 2 瓶应退 **52.92**。分两次，程序两次都给 99.40 − 81.76 = 17.64，合计 **35.28，少退 17.64**。
  - 满减 + 店铺原因（活动按比例保留）分次和一次一样，都是 58.80，这一种没问题。
- 实跑结果和上表完全一致（70.56 / 35.28 / 58.80）；三种情况 `CheckOrderMoney` 都报 0 个问题，说明现有验算查不出这个错。
- 把菜全部退完时，最后一道给“剩下的全部”（S11），总数会对上；错只出在**退了两次以上、但没退完**的单上。
- 触发条件：订单带菜品活动或有门槛的活动/券，分两次以上按菜退款。
