# 客户地址和送餐热力图 设计方案（v0.1，2026-11-23，待 brian 确认）

brian 的要求：

1. 商家新增一个地址管理页面，能看到自己所有客户的地址列表。
2. 统计：某段时间内（最多一个月）送餐最多的地址。
3. 打开谷歌地图，把这段时间（最多一个月）内所有送餐地址标在地图上。
4. 在地图上按送餐次数画热力图。
5. 管理员端也要有。

本方案只涉及商家后台和平台后台，顾客端不出现任何地址统计，也不出现配送区。

## 1. 业内怎么做

| 平台 | 做法 | 能看到什么 |
|---|---|---|
| DoorDash 商家后台 | Customers → Customer Insights：新客 / 偶尔 / 常客的比例，加一张“顾客下单位置和邮编”的热力图 | 只看本店；地图是聚合后的热度，不列具体顾客 |
| Uber Eats Manager | Customer insights：哪些地区带来的销售最多、新老客比例、下单频率和留存 | 按地区聚合的数字，没找到公开资料说明有逐个地址的地图 |
| 美团 / 饿了么商家版 | 官方公开介绍里只有订单、结算、营销、配送范围设置，没找到“顾客分布热力图”的公开说明（可能在数据中心里，但查不到资料，不作依据） | 第三方平台上商家看不到顾客完整地址的统计 |
| 自配送 SaaS（我们这类） | 店家自己送，本来就有每单的完整地址；常见做法是“顾客地址簿 + 热门地址排行 + 地图标点 / 热力” | 本店全部数据 |

几点结论：

- **大平台给商家的都是聚合数据**（热度、地区排行），因为地址是平台的顾客隐私。我们是商家自配送，订单页本来就显示完整地址，所以可以给逐个地址，但仍然只看本店、不能导出全平台数据。
- **排行 + 地图 + 热力**是标准组合：排行回答“哪里点得最多”，标点回答“具体在哪”，热力回答“哪片区域密”。
- **时间范围要限**：DoorDash、Uber 都按时间段看，和 brian 说的“最多一个月”一致，同时也控制了一次查询的数据量。

### 技术上的一个关键点：谷歌自带的热力图已经下线

谷歌地图 JavaScript API 的 `HeatmapLayer`（visualization 库）2025 年 5 月宣布弃用，2026 年 5 月的版本起不能用了，谷歌推荐改用 deck.gl。我们不用它，也不引入 deck.gl（几百 KB）：现有的 `MapCanvas.vue` 本来就是在谷歌地图上叠自己的绘图层（配送区就是这么画的），热力图同样在这层上用 canvas 自己画，几十行代码。好处是不依赖谷歌哪天再改接口，而且测试用的模拟地图（`GOOGLE_MAPS_API_KEY=stub`）上也能画，浏览器测试可以覆盖。

## 2. 数据从哪来

**不新建表**，全部从订单算：

- 范围：外卖单（`service_type = 'delivery'`），包括顾客自己下的单和代客下单。
- 不算：拒单、取消单、配送失败的单（和会员页的消费统计口径一致，再加上配送失败，因为没送到）。
- 地址：`orders.address_line`、`address_unit`，位置 `orders.dest_lat / dest_lng`。
- 客户：顾客下单按 `customer_id`，代客下单按 `member_id`，都没有时按电话号码 `customer_phone`。
- 时间：按下单时间 `created_at`，用**门店的时区**（`branches.timezone`）划分日期。

**“同一个地址”怎么认**：用地址库已有的比对函数 `addr_key()`（全半角、大小写、空格标点都忽略），按 `addr_key(address_line)` 归为一个地址，也就是**按楼 / 按门牌号以外的地址**合并；门牌（`address_unit`）不同的算同一个地址下的不同户，排行里展开能看到。这样“同一栋写字楼送了 80 单”能排到前面，而不是被拆成 30 个门牌各两三单。

一个地址的位置取它最近一单的经纬度；没有经纬度的地址能进列表和排行，但不上地图，地图上方提示“有 N 个地址没有定位，不在地图上”。

**索引**：已有 `orders (branch_id, created_at DESC)`。迁移 00052 加一个部分索引 `orders (branch_id, created_at) WHERE service_type = 'delivery'` 给统计和地图用；管理员看全平台时加 `orders (created_at) WHERE service_type = 'delivery'`。

## 3. 商家端：客户地址页 `/merchant/addresses`

菜单放在“会员”下面，名字“客户地址”。权限和会员页一样：店长、经理、收银可见。只看本店（多门店的商家按当前门店）。页面顶部三个标签：**地址列表 / 送餐排行 / 地图**。

### 3.1 地址列表（要求 1）

所有下过外卖单的客户地址，不限时间。

```
[搜索 地址 / 姓名 / 电话 ]  [来源：全部 ▾]  [排序：最近下单 ▾]

地址                         门牌      客户            单数   最近下单      
Ayala Tower One, 6750 Ayala  23F 2301  王先生 0917…   12    11-22 12:05   查看 · 订单
                                       会员 #100023
SM Aura Premier, BGC         —         Li 0918…        3    11-20 19:40   查看 · 订单
```

- 一行 = 一个客户的一个地址（客户 + 地址键 + 门牌）。
- 列：地址、门牌、客户姓名和电话（有会员号就显示，点开跳会员页）、累计单数、首次和最近下单时间、有无定位。
- 搜索：地址、姓名、电话都能搜，地址词序不限（同地址库的匹配方式）。
- 来源筛选：全部 / 顾客自己下单 / 代客下单。
- 排序：最近下单、单数最多、最早下单。
- “查看”：有经纬度时直接打开谷歌地图网页（拼 URL，不调接口，和地址库一样）；“订单”：列出这个客户在这个地址的订单。
- 分页，每页 50 条。
- 手机上每行变成卡片。

### 3.2 送餐排行（要求 2）

```
时间 [2026-10-24] 到 [2026-11-23]   快捷：今天 · 近 7 天 · 近 30 天 · 上个月
（最多 31 天）

合计 1,284 单 · 416 个地址 · 平均每个地址 3.1 单

#  地址                          单数   占比   客户数   金额        最近一次
1  Ayala Tower One, 6750 Ayala    86   6.7%    31   ₱ 41,280    11-23 12:40   查看 ▸
2  SM Aura Premier, BGC           54   4.2%    22   ₱ 23,900    11-23 11:58   查看 ▸
…
```

- 时间范围最多 31 天（“一个月”按 31 天算，跨大月也能选满一个自然月），超过时日期框标红，按钮不可点。默认近 30 天。
- 按地址键合并后的单数从多到少，列出前 100 名。
- 每行：地址、单数、占全部单数的比例、不同客户数、订单金额合计（按门店货币）、最近一次。
- 点“▸”展开：这个地址下的门牌 / 客户明细（每户几单）。
- “在地图上看”：切到地图标签并定位到这个地址。

### 3.3 地图（要求 3、4）

```
时间 [2026-10-24] 到 [2026-11-23]   显示：(●) 标点  ( ) 热力  ( ) 两个都显示
[✓] 显示配送区轮廓     热力半径 ──●── 

┌──────────────────────── 谷歌地图 ────────────────────────┐
│     ⑫                                                    │
│          ③   🏠门店        ●5                              │
│                 (86)                                      │
└───────────────────────────────────────────────────────────┘
有 7 个地址没有定位，不在地图上
```

- 用现有的 `MapCanvas`（谷歌地图，密钥在后台 `/admin/settings` 配置；没配真密钥时用模拟地图）。打开时自动缩放到能看到门店和全部点。
- 门店位置用店铺图标标出。
- **标点**：每个地址一个圆点，圆点大小和颜色深浅跟单数走，单数写在点里。缩小地图时点太密，按屏幕网格合并成一个带总数的圆（常见的“聚合标点”），放大后再散开。点一下弹出小卡片：地址、单数、客户数、最近一次、“打开谷歌地图”、“看排行明细”。
- **热力**：每个地址按单数加权，在自己的 canvas 层上画高斯模糊的热度，颜色从透明 → 金色 → 橙 → 深红（和后台配色一致）。“热力半径”滑块调模糊范围（默认 30 像素，跟随缩放），用来在“看清单个热点”和“看整片区域”之间切换。
- **配送区轮廓**：商家端可勾选叠加本店配送区的边线（只在商家后台和平台后台，顾客端不显示），方便看哪片热区在配送区外、要不要扩区或调配送费。
- 时间范围和排行共用同一组日期，切标签不丢。
- 一次最多返回 20,000 个地址点（一家店一个月远到不了这个数）；超过时提示缩短时间。

### 3.4 “打开谷歌地图”的说明

brian 说“打开谷歌地图把所有送餐地址标注出来”。谷歌地图网页版的链接一次只能带一个点，没法把几百个点放进一个链接。所以：

- **页面里嵌的就是谷歌地图**（同样的底图、街道、卫星图切换），在上面标点和画热力，这是主做法。
- 单个地址的“查看”打开谷歌地图网页 / App，方便骑手导航。
- 如果以后想在谷歌自己的 “My Maps” 里看，可以加一个“导出 KML”按钮（谷歌 My Maps 能直接导入）。首版不做，见第 7 节。

## 4. 管理员端：送餐地址页 `/admin/delivery-addresses`

`/admin/addresses` 已经是平台地址库（PR #86），这个新页面叫“送餐地址”，放在它旁边。三个标签和商家端完全一样（同一个组件，`admin` 属性），多一行筛选：

```
商家 [全部商家 ▾]  门店 [全部门店 ▾]  国家 [全部 ▾]  城市 [全部 ▾]
```

- 可以选“全部商家”，也可以选某个商家、某个门店；国家 / 城市按门店所在地区筛（门店的地区字段已有）。
- 地址列表、排行多一列“门店”。选全部商家时，排行按“门店 + 地址”分开算还是合在一起算：**合在一起算**（看全平台哪些楼单最多），展开能看到每家店各送了几单。
- 地图：选全部商家时用平台主题色画热力，门店都标出来；选了门店才显示配送区轮廓。
- 时间同样最多 31 天。全平台的数据量大，地图点超过 20,000 个时要求先选国家或城市。
- 管理员查看完整顾客电话等个人信息，和会员管理页一样不另外记操作记录（只读）。

## 5. 接口

商家端（门店权限同会员页）：

- `GET /merchant/branches/:bid/customer-addresses?q=&source=&sort=&page=` 地址列表
- `GET /merchant/branches/:bid/customer-addresses/orders?key=&unit=&customer=` 某客户某地址的订单
- `GET /merchant/branches/:bid/delivery-stats/top?from=&to=` 排行（前 100，含展开明细）
- `GET /merchant/branches/:bid/delivery-stats/points?from=&to=` 地图点：`[{lat, lng, count, label}]`

管理员端：同样四个，路径 `/admin/delivery-addresses…`，多 `merchant_id`、`branch_id`、`country_code`、`city` 参数。

服务器检查：`from`、`to` 必填，`to - from ≤ 31 天`，否则 400。日期按门店时区换算；管理员跨时区看全部时，每家店按自己的时区。

后端代码放 `internal/app/delivery_stats.go`，前端共用组件 `web/src/views/addresses/DeliveryAddressBook.vue`，热力层 `web/src/views/addresses/HeatLayer.vue`（canvas，挂在 MapCanvas 的绘图层上）。文案前缀 `da.`，12 种语言都补。

## 6. 我定的取舍（可以改）

| # | 问题 | 推荐 | 其他选择 |
|---|---|---|---|
| 1 | 哪些单算“送餐” | 外卖单，去掉拒单、取消、配送失败 | 只算已送达的；或所有外卖单 |
| 2 | 同一个地址怎么合并 | 按地址文字合并（忽略门牌），门牌在展开里看 | 按地址 + 门牌（每户单独排）；或按经纬度 50 米内合并 |
| 3 | 时间按什么算 | 下单时间，门店时区 | 送达时间 |
| 4 | “最多一个月” | 最多 31 天，默认近 30 天 | 自然月选择器 |
| 5 | 商家端谁能看 | 店长、经理、收银（同会员页） | 只给店长、经理 |
| 6 | 地址列表的时间 | 列表不限时间（客户地址簿），排行和地图才限 31 天 | 列表也限时间 |
| 7 | 热力图实现 | 自己在 canvas 层画（谷歌热力层已下线，模拟地图也能测） | 引入 deck.gl |
| 8 | 管理员选全部商家时排行 | 同一地址跨店合并 | 按门店分开排 |

## 7. 首版不做

- 导出 Excel / KML（可以第二步加，KML 能导入谷歌 My Maps）。
- 按时段（午市 / 晚市）、按星期筛选热力。
- 新客 / 老客分布（DoorDash 有，以后可加）。
- 热区自动建议调整配送区。
