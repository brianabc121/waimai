## 1. 要解决什么

brian 的原话：代客下单页面这里还需要新增一个堂食模式。堂食模式只需要点点点，尽可能减少键盘输入。

现在的代客下单页（`/merchant/orders/new`）是为“顾客在微信里发消息、店员在电脑前替他下外卖单”设计的，键盘优先：输会员号、电话、地址、菜品编号。堂食正好相反：服务员站在桌边或收银台前，拿着 iPad 或手机，顾客说一道店员点一道，**全程用手指点，不打字**。

拆成四件事：

1. **选桌**：一眼看到哪些桌空着、哪些在吃、哪桌有菜没上、哪桌坐太久。
2. **开台**：点人数，不打字。
3. **点菜**：菜品大格子一点就加；规格和口味全部点选（用 PR #102 的口味模板）；一轮点完一次送厨。
4. **桌上的事**：加菜、上桌、退菜、换桌、结账，也全部点选。

## 2. 现在系统里已经有什么

堂食的后端在第一期第五批（PR #5）就做好了，这次**主要是做店员用的触屏前台**，后端只补几样小东西（第 10 节）。

| 已有 | 说明 |
|---|---|
| 桌台 `dining_tables` | 桌名、桌码、启用、排序。没有区域、没有座位数 |
| 桌次 `dining_sessions` | 开台到关台，记人数；一张桌同时只有一个桌次 |
| 一桌一张账单 | `service_type = dine_in` 的订单，单号 D 开头；每次下单是一个批次（轮），`order_batches.source` 记来源（扫码 / 平板 / 店员） |
| 加菜接口 | 幂等键、按当前菜单重新计价、价格变了就拒绝、按工作台派单 |
| 上桌、退菜 | `served_at`、`void_reason`；退菜必须写原因 |
| 结账关台 | 清单版本号防止“钱收了但新加的菜没算”；有菜在做不能关台；实收不少于应付 |
| 菜品“堂食”开关 | PR #57，后端报价时已经按堂食过滤 |
| 口味模板 | PR #101 方案、PR #102 实现：模板 → 组（单选/多选）→ 标签，订单行存 `note_tags` |
| 店员页面 | `/merchant/tables` 桌台页：开台、看账单、加菜、退菜、收款，还有桌码和平板配对。**它是电脑上用的列表加弹窗**，加菜用的是顾客菜单组件，退菜原因用浏览器 `prompt()` 打字 |

结论：数据和规则都够用，缺的是“为手指设计”的界面，加上几样业内都有、我们还没有的小功能（区域、座位数、整轮要求、付款方式、换桌）。

## 3. 业内怎么做

| 产品 | 做法 | 借鉴 |
|---|---|---|
| Toast（美国全服务餐厅 POS） | Table Service 模式先看桌台图，桌子按订单状态变色；开台先输客人数；点菜屏左边菜单分组、中间菜品按钮、右边账单；有 Send / Stay / Hold（送厨、留着、暂缓）；可选按座位点、按道（course）出菜；长按桌台可移桌 | 桌台图变色；开台输人数；送厨按钮；长按/按钮换桌 |
| Square for Restaurants | 平板和手机都能桌边点单：在桌台图点一桌 → 选人数 → 点菜；修饰项（modifier）可加价可不加价，可整组套给一类菜；道菜（course）手动“开火”送厨，饮料、沙拉可设自动直接送 | 手机桌边点单；不加价的口味和加价的规格分开；饮料先上 |
| Lightspeed Restaurant | 按桌、按座位、按道菜三种方式记菜；送厨后不能再改座位和道次 | 送厨后锁定（我们已有：送厨的轮不能改，只能加或退） |
| 美团收银 / 美团服务员 | 收银机和服务员手机两端；桌台管理、快捷点菜、一键下单到收银台和后厨；开台录人数（新版可录儿童数）；联台时可选部分桌加菜；另有“直接点餐”（快餐不选桌） | 服务员手机端；开台人数；快餐模式我们先不做 |
| 客如云 / 哗啦啦 点菜宝 | 服务员手持点菜；桌台详情里点菜、催菜、划菜（上桌）、退菜、换台、并台、清台、结账；做法和口味预设一点就加 | 催菜、上桌、退菜、换台都放在“点一道菜/一张桌后弹出的按钮”里；做法口味点选 |

共同点，也是本方案的做法：

- **先桌台、后点菜**：首页就是桌台图，颜色说明状态；点空桌开台，点在用的桌进入。
- **人数点选**：开台第一步点人数（1 到 12 的大按钮），不弹键盘。
- **菜品是大按钮**：按分类排，点一下加一份；有必选项才弹框。
- **规格和口味分开**：加钱的、必选的叫规格；不加钱的口味（少辣、去冰）用模板标签。
- **一轮一送**：点完一轮按“送厨”，送过的不能改，只能加新的一轮或退菜。
- **桌上的操作放在桌和菜上**：点桌出“加菜 / 账单 / 结账 / 换桌”，点菜出“上桌 / 再来一份 / 催一下 / 退菜”。
- **原因、金额也点选**：退菜原因是预设按钮；收款有“刚好”和整数快捷金额，再不够用屏幕数字键。

不照搬的：

- **按座位点菜（seat）**：西餐分开结账才用。我们的顾客多是一桌合点合付，且已确认不分单。不做。
- **按道菜出菜（course / 等叫起菜）**：中餐馆也有“等叫”，但会让后厨屏变复杂。首版只做“整轮要求”里的“先上饮料 / 菜齐再上 / 加急”提示，后厨看得到，不改出菜流程。真正的“暂缓送厨、叫起再做”放第二批（第 12 节问题 4）。

说明：Toast、Square、Lightspeed 的做法来自它们公开的帮助文档；美团、客如云、哗啦啦的帮助文档不公开，来自应用商店介绍和公开资料，细节以它们实际后台为准。

## 4. 入口和整体流程

- 代客下单页顶栏加一个切换：**外卖 / 自取 | 堂食**（效果图 01）。地址栏也能直接打开：`/merchant/orders/new?mode=dine`。
- 这台设备上次用的是哪个模式，下次打开还是哪个（存在本机）。门店没有桌台时，“堂食”按钮灰掉，提示“先在桌台页添加桌台”。
- 外卖模式完全不变（键盘优先，照旧）。

```
桌台图 ──点空桌──▶ 开台（点人数）──▶ 点菜 ──送厨──▶ 回到桌台图（这桌变成“用餐中”）
   │
   └──点在用的桌──▶ 右边概况：加菜 / 账单·退菜 / 结账 / 换桌 / 改人数
```

送厨后默认回到桌台图（服务员通常要去下一桌）；在设置里可以改成“留在这一桌”。

## 5. 桌台图（效果图 01）

- 上面一排**区域**按钮：全部 / 大厅 / 包间 / 露台…，后面带桌数。区域在桌台设置里给每张桌点选（第 10 节）。
- 桌台格子按桌台设置里的顺序排，iPad 一行 5 张，电脑一行 6 到 8 张，手机一行 3 张。
- 每张桌显示：桌名（大字）、人数/座位数、已点金额、坐了多久、第几轮。
- 颜色（图例在右上角）：
  - **空闲**：白底虚线框，写“点一下开台”。
  - **用餐中**：浅金底。
  - **有菜没上**：橙底，右上角橙色角标“3 道没上”（制作中和已备好但没上桌的份数）。
  - **坐超 90 分钟**：浅红底，角标变红。90 分钟可在设置里改。
  - 开了台还没点菜：浅金底，金额处写“还没点菜”。
- 右边栏是**选中这桌的概况**：金额、时长、没上的菜数，以及每道菜的状态（已上桌 / 已备好 / 制作中几分钟）。下面是大按钮：**＋加菜**、**账单/退菜**、**结账**、**换桌**、**改人数**。
- 手机上没有右边栏：点在用的桌直接进入点菜屏，顶上的桌号按钮能切到账单和结账。
- 桌台状态实时更新（沿用现有的门店事件推送），其他服务员、扫码顾客加的菜马上能看到。

## 6. 开台（效果图 02）

- 点空桌弹出开台框：**几位客人**是 1 到 11 的大按钮，第 12 个是“12 以上 ＋”（点了变成加减按钮）。默认选中这张桌的座位数。
- **这桌备注**（选填、点选，可多选）：有小孩、有老人、赶时间、生日、VIP、＋其他。预设标签在设置里改。后厨票和小票的桌号旁边显示。“＋其他”是这一页少数能打字的地方。
- 两个按钮：“只开台”（先让客人坐下看菜单，或者让客人自己扫码点）和“开台并点菜”。
- 改人数：右边栏“改人数”，弹同样的数字按钮。

## 7. 点菜（效果图 03、04）

### 7.1 布局（iPad 横屏 / 电脑）

- **顶栏**：“‹ 桌台”返回；金色桌号块“A3 · 3 人 · 42 分”；“第 3 轮加菜”。
- **左边分类竖栏**：分类和顾客点餐页一样；第一项是“常点”（这家店最近 30 天堂食点得最多的 20 道）。分类旁的红数字是这一轮在这个分类点了几份。
- **中间菜品格**：一行 4 个大格子（手指好点），**上面是菜品图片**（菜品主图，和顾客点餐页同一张，裁成横图），左上角压着编号；下面是菜名、价格，以及“规格”“口味”小标记。iPad 一屏能看到 12 道菜。
  - 没上传图片的菜，图片位置显示菜名前两个字（米色底），格子大小不变，排列整齐。
  - **点一下加一份**，格子右上角出现红色数字。
  - 有**必选规格**或套了**口味模板**的菜，点一下弹出选择框（7.3）。只有可选加料、没有口味模板的菜，直接加一份基础款，在右边点那一行再改。
  - 售完的灰掉写“售完”；限量的写“剩 2”。不能堂食的菜（PR #57 的供应方式）不显示。
  - 售完的菜图片变灰。
  - 图片用缩略图（和商城、点餐页同一套尺寸），不会拖慢 iPad。
- **中间顶上**：“全部 / 招牌 / 辣”是菜单里已有的标签筛选；“🔢 按编号点”打开屏幕上的编号键盘（字母和数字的大按钮，点 C、1、2 就跳到 C12），给熟手用，也不用系统键盘。
- **右边“这一轮”**：这一轮还没送厨的菜，每行有小图、规格、口味标签、加减按钮和小计。
  - 点一行：重新打开 7.3 的选择框改规格和口味，或删除。
  - **整轮要求**（点选，可多选）：先上饮料、菜齐再上、全部少辣、分小碗、加急。预设在设置里改。送厨后显示在后厨票这一轮的抬头上。
  - “已送厨 2 轮 · 5 道 ₱860 查看 ›”：点开看账单（第 8 节）。
  - 底部：这一轮合计，**送厨（5 份）**大按钮，“取消”（清空这一轮回桌台，要确认）。
- 这一轮存在本机（沿用现在的做法：购物车和幂等键存本机），网络断了或者不小心退出，回到这桌还在。

### 7.2 送厨

- 调用现有加菜接口，批次来源记 `staff`，带上点菜的店员。
- 价格变了（有人刚改了菜价或售罄），弹提示显示新金额，店员点“按新价格送厨”再送。这是现有规则。
- 送厨成功：短暂提示“A3 第 3 轮已送厨”，回到桌台图。

### 7.3 选规格和口味（效果图 04）

- 弹框顶上是菜品大图，然后从上到下：
  1. **规格**（加钱的、必选的，来自菜品的选项组）：大按钮，单选组点一个，多选组可点多个，价格写在按钮里。必选的组标“必选”，没选时“加入”按钮是灰的，并把那一组标红。
  2. **口味模板**（PR #102）：一条虚线分开，每组一行，写明“单选 / 可多选，不加钱”。
  3. 最后一组后面有“＋ 手写一条”：唯一会弹键盘的地方，平时用不到。
  4. 底部：数量加减（大按钮），已选内容的一行摘要，“加入这一轮 ₱560”。
- 同一道菜选了不同口味，分成两行（例如一碗微辣、一碗不辣）。

### 7.4 手机版（效果图 06 ②）

- 和顾客点餐页同一种排法：左边分类，右边菜品列表，每行左边是菜品图片，右边“＋”或“选规格”。
- 底部深色条：“这一轮 5 份 ₱910 送厨”，点左边展开这一轮清单（和整轮要求）。
- 选规格和口味用底部面板，内容同 7.3。

## 8. 账单、上桌、退菜（效果图 05、06 ③）

- 按轮次分段：“第 1 轮 18:02 · 店员 阿玲”“第 2 轮 18:20 · 顾客扫码”，整轮要求也写在这里。
- 每道菜有状态：制作中（几分钟）、已备好、已上桌、已退。
- **点一道菜**，下面出一排按钮：
  - **上桌**：已备好的菜才能点（现有规则）。
  - **再来一份**：把这道菜（同规格同口味）放进新的一轮，直接跳到点菜屏。
  - **催一下**：后厨屏这道菜标“催”，并响一声。见第 12 节问题 6。
  - **退菜**：底部面板（效果图 06 ③），选退几份，原因点选：点错了、顾客不要了、上太慢、菜品有问题、沽清了、＋手写。预设在设置里改。替换现在桌台页的 `prompt()` 打字。
- 退菜的权限和经理授权码沿用 PR #97 到 #99：没有退菜权限的人点“退菜”，弹经理授权码（数字键盘点选）。

## 9. 结账关台（效果图 05 右边）

- 上面：菜品份数、服务费、税、**应付**（沿用现有算法）。
- **付款方式**点选：现金、刷卡、电子钱包（菲律宾显示 GCash、Maya；按店铺国家给默认选项，设置里可改）、转账。见第 12 节问题 5。
- **实收**：大字显示；下面一排快捷金额：“刚好”、比应付大的三个整数（按币种取整，比如 ₱1,485 → ₱1,500 / ₱2,000 / ₱3,000）；再下面是屏幕数字键（1 到 9、00、0、退格）。不是现金时默认“刚好”，不显示数字键。
- **找零**自动算。
- “收款并关台”：沿用现有规则（版本号对不上就刷新金额重新确认；有菜在做时按钮灰掉，提示先上桌或退菜；实收不能少于应付）。
- 关台后弹小票：“打印小票”“完成”。打印沿用现有小票页。

## 10. 改动清单

### 10.1 数据库（一个迁移）

| 表 | 新字段 | 说明 |
|---|---|---|
| `dining_tables` | `area TEXT NOT NULL DEFAULT ''` | 区域名，桌台设置里点选或新建 |
| `dining_tables` | `seats INT NOT NULL DEFAULT 4` | 座位数，开台默认人数、桌台图显示“4 人桌” |

### 10.2 接口

- `GET /merchant/branches/{id}/tables` 加区域、座位数、每桌没上菜数（已有金额、时长）。
- `POST /merchant/tables/{id}/open` 加 `tags`。
- `PATCH /merchant/table-sessions/{id}` 改人数、改这桌备注。
- `POST /merchant/table-sessions/{id}/batches` 每行带 `note_tags`（PR #102 给下单报价加的字段，这里同样接上），整轮加 `round_tags`。
- 新增 `POST /merchant/table-sessions/{id}/move`（换桌，目标必须是空桌，同一事务改桌次和订单的 `table_name`，推送两张桌的更新）。
- 新增 `POST /merchant/bill-items/{id}/rush`（催菜）。
- 退菜接口加 `qty`（退几份；现在是整行退，几份同一行时拆行）。
- 关台接口加 `pay_method`。
- 常点：`GET /merchant/branches/{id}/dine-top`，最近 30 天堂食前 20 道。
