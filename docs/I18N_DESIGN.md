# 多语言支持 · 设计方案 v0.2

2026-11-23 · brian 已确认，第 12 节的问题全部按推荐做法，分四批实现。

本稿讲全站多语言：顾客、商家、员工页面都能用 12 种语言显示；商家只录一种语言的菜单，系统自动翻译成其他语言，商家可以手动改；店铺名称等店铺信息只做简体中文、英文、繁体中文三种，其他语言一律显示英文；平台后台新增“语言适配”页，管理员核对和纠正每个页面的译文。

效果图在 [i18n-screens/](i18n-screens/)，可点开的 HTML 原型在 [i18n-prototype/](i18n-prototype/)（`index.html?s=mall｜store｜item｜storeinfo｜admin`）。店名、菜名、译文都是示意数据，泰文、阿拉伯文、缅甸文等示意译文没有经过母语者核对。

## 2. 业内怎么做

### 2.1 外卖和电商平台

| 平台 | 做法 | 和我们的关系 |
|---|---|---|
| **Grab** | App 界面跟随用户选的语言（2023 年加了中文、日文、韩文）。商家菜单用自研的机器翻译模型翻成英文等语言，每条译文带一个置信度分数；顾客在菜单页点翻译图标切换语言。2023 年先在越南 5 个城市试点英文菜单。 | 和你的设想最接近：菜单自动翻译 + 顾客可切换。我们照着做“机器翻译提示 + 查看原文”。 |
| **Glovo** | 菜单机器翻译用第三方引擎 ModernMT，用自己的历史翻译和热销商品数据训练，并维护术语表保证同一个词译法一致。 | 术语表的思路以后可以做成商家的“不翻译的词”列表，这次不做。 |
| **Shopify** | 官方 Translate & Adapt 应用：机器翻译用 Google Cloud Translation，每家店最多自动翻译 2 种语言，手动翻译不限。原文改动后，已有译文标为“过期”，提醒商家重看。 | “原文改了，人工改过的译文不覆盖，只标待核对”就是学这个（第 6.3 节）。 |
| **Uber Eats、DoorDash、foodpanda** | 界面跟随手机语言；菜单一般就是商家原文，部分市场由商家自己填两种语言（比如当地语言 + 英文）。没查到官方公开的菜单自动翻译功能（只有第三方资料，未核实）。 | 这些平台的店名基本不翻译，或由商家给英文名，和你“店铺信息由商家自己管、英文兜底”一致。 |
| **美团 Keeta** | 没有查到可靠的公开资料说明它怎么处理菜单翻译，不展开。 | |

归纳下来，业内常见的做法是三条：

1. **界面文字跟随用户语言**，第一次按设备或浏览器语言，之后以用户手动选的为准。
2. **商家录的内容（菜单）**：原文 + 机器翻译，顾客能看出是机器翻译、能切回原文；商家能改译文。
3. **店名、品牌名**不交给机器，商家自己提供英文名或不翻译。

### 2.2 网页多语言的常用工具

- **界面文字框架**：Vue 常用 vue-i18n，通用的有 i18next。它们解决的是：按语言加载文字文件、`{n}` 这样的变量、复数（俄语有 3 种复数形式，阿拉伯语有 6 种）、日期数字格式。复数和日期数字格式的规则来自 Unicode CLDR，浏览器自带的 `Intl` 已经实现。
- **翻译管理平台**：Crowdin、Lokalise、Weblate（开源，可自建）。它们都有“在页面上点文字直接改译文”的功能。我们的后台“语言适配”页就是一个简化版，只服务这个系统，不引入外部平台。

### 2.3 机器翻译服务和费用

| 服务 | 整份菜单翻一次 |
|---|---|
| Google（普通） | 约 $2.4（每月免费额度够翻约 4 家店） |

## 4. 三类文字，三种规则

系统里的文字分三类，翻译方式和兜底顺序不同：

| 类别 | 例子 | 谁来翻 | 有哪些语言 | 显示顺序（取第一个有的） |
|---|---|---|---|---|
| **A. 界面文字和系统消息** | 按钮、标题、提示、订单状态、短信、推送、站内消息、Excel 表头、平台的商城分类和活动图 | 实现时一次翻好放进仓库；管理员在“语言适配”页纠正 | 12 种 | 当前语言 → 英文 |
| **B. 菜单类内容** | 菜品名、描述、详情、分类名、规格组名、选项名、店铺优惠活动名、商家优惠券名 | 商家录一种，系统自动翻；商家可改 | 12 种 | 当前语言 → 英文 → 原文 |
| **C. 店铺信息** | 店名、店铺简介、店铺公告 | 商家自己填，系统只做辅助 | 只有简中、英文、繁中 | 当前语言是这三种之一时显示对应的；其余语言 → 英文 → 原文 |

不翻译、照原样显示的：地址、电话、门牌、顾客写的备注、评价、聊天消息、商家回复（问题 10）。

## 5. 顾客怎么得到自己的语言

### 5.1 第一次打开

按顺序找，找到就用：

1. **网址里的 `?lang=th`**（分享链接时带上，打开后同时写入 cookie）
2. **cookie `lang`**（以前手动选过或自动识别过）
3. **登录顾客保存的语言**（换了新手机、新浏览器时用）
4. **浏览器语言**（服务器读请求头 `Accept-Language`，前端读 `navigator.languages`），按偏好顺序取第一个支持的
5. 都没有就用**英文**

浏览器语言怎么对应：`zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant` → 繁体中文；`zh`、`zh-CN`、`zh-SG`、`zh-Hans` → 简体中文；其余按前两个字母（`th-TH` → 泰语，`fr-CA` → 法语，`my-MM` → 缅甸语）。

### 5.2 cookie 和“更快”

识别出语言后写一条 cookie：`lang=th; Path=/; Max-Age=一年; SameSite=Lax`。

用 cookie 而不是现在的 `localStorage`，是因为**服务器能读到 cookie**：Go 返回首页 HTML 时就把 `<html lang="th" dir="ltr">` 写好，并让浏览器预先下载泰语文字包。这样页面一出来就是泰语、方向正确，不会先闪一下中文再变。阿拉伯文尤其需要这样，不然整页会先左后右跳一次。

### 5.3 手动修改

商城首页、点餐页右上角加一个语言按钮（地球图标 + 当前语言名，如“🌐 ไทย”），点开是语言面板（效果图 ②）：

- 每种语言用自己的文字写，右边附英文名，选错了也能找回来。
- 最上面一行“跟随浏览器”，选它就删掉手动选择，回到自动识别。
- 选完立即切换，不刷新页面，同时更新 cookie；登录的顾客同时保存到账号。

“我的”页面、订单页、结算页也放同一个按钮（现在那几个“EN / 中文”按钮换成它）。商家后台、员工工作台、后厨的语言在各自的设置里选，同样写 cookie。

### 5.4 机器翻译的提示

点餐页顶部，当前语言的菜单里有机器翻译的内容时，显示一行“菜单是机器翻译的 · 查看原文”（效果图 ③④）。点“查看原文”整份菜单切回商家原文，再点切回来。这是学 Grab 的做法，让顾客知道译文可能不准，看不懂时能对照原文问商家。

## 6. 菜单自动翻译

### 6.1 商家怎么用（效果图 ⑤）

1. 店铺设置里有“菜单原文语言”，默认是商家开店时用的界面语言，比如简体中文。商家录菜品、分类、规格都用这种语言（问题 9）。
2. 商家保存菜品后，几秒内系统在后台把菜名、描述、详情、规格名翻成另外 11 种语言。繁体中文用简繁转换，其余用机器翻译。
3. 编辑菜品页右边有“多语言”卡片：按字段（菜名 / 描述 / 详情 / 规格）切换，列出 11 种语言的译文和状态，每条都能点“改”手动修改。
4. Excel 批量导入（PR #70）导入的菜品一样自动翻译，按 50 道一批送去翻译。
5. 菜单页加一个“多语言核对”视图：一行一道菜，一列一种语言，方便整份菜单过一遍。商家只关心自己顾客常用的几种语言时，可以只看那几列。

### 6.2 每条译文的状态

| 状态 | 什么时候 | 原文再改时 |
|---|---|---|
| 机器翻译 | 系统自动翻的 | 自动重翻 |
| 简繁转换 | 繁体中文由简体自动转换 | 自动重转 |
| 商家已改 | 商家手动改过或点了确认 | **不覆盖**，标成“原文改过，待核对” |
| 原文改过，待核对 | 见上 | 商家改一下或点“保持不变”后回到“商家已改” |

商家可以随时点“全部重新机器翻译”，会覆盖所有“机器翻译”状态的译文；“商家已改”的要逐条确认才覆盖。

### 6.3 数据怎么存

不在每张表加 11 列，而是新加一张译文表，所有要翻译的内容共用：

```
content_translations
  entity      菜品 / 分类 / 规格组 / 选项 / 优惠活动 / 优惠券 / 门店 / 商城分类 / 活动图
  entity_id   对应那条记录
  field       name / description / details / intro / notice / title / subtitle
  lang        zh-Hans、en、th……
  text        译文
  status      machine / converted / human / stale
  source_hash 翻译时原文的摘要（原文变了就知道这条过期了）
  provider    用哪个服务翻的
  updated_by、updated_at
  唯一键 (entity, entity_id, field, lang)
```

- 现在各表的 `name`、`description` 等列继续存**原文**；门店新增 `menu_lang`（菜单原文语言）。
- 现有数据全部是中文原文，`menu_lang` 设为简体中文；现在的 `name_en` 迁移成英文译文，状态“商家已改”（因为是人填的）。`name_en` 列先保留一段时间，确认没人读了再删。
- 顾客端接口按当前语言直接返回算好的名字，另带原文和“是否机器翻译”，前端不用自己挑。点餐页的菜单按 (门店, 语言) 缓存。
- 商城搜索菜名时在原文和所有译文里一起找，泰语顾客搜泰文也能搜到中文菜单的店。

### 6.4 订单和后厨

- 下单时订单明细保存两份菜名：**原文**和**顾客当时语言的译文**（现在存的是中文 + 英文）。订单上记下顾客的语言。
- 顾客看订单用译文；后厨、打包、小票、骑手、商家后台用原文，因为店员按商家自己的菜单做菜。
- 店员的界面语言（按钮、状态这些）照样跟随店员自己的设置。

### 6.5 翻译怎么跑

- 用现有的任务队列（Worker）。商家保存后排一个翻译任务，同一道菜几秒内连续保存只翻最后一次。
- 一次调用把一道菜（或一批 50 道菜）的所有字段翻成一种语言，要求返回 JSON，按编号对回去。
- 给翻译模型的要求：这是餐厅菜单；目标语言有通行叫法的用通行叫法（宫保鸡丁 → Kung Pao Chicken），没有的音译加简短说明（避免“夫妻肺片”直译）；品牌名、店名不翻；数字、单位、价格、`{占位符}`、表情符号原样保留；不添加原文没有的信息。
- 翻译失败自动重试；一直失败的在商家菜品页显示“翻译失败，点这里重试”，顾客端按兜底顺序显示英文或原文，不影响下单。
- 没填翻译密钥时：繁体中文照样转换，其他语言不翻，顾客看到英文（有的话）或原文。

## 7. 店铺信息（效果图 ⑥）

- 店名、店铺简介、店铺公告各有三格：简体中文、英文、繁体中文。商家录其中一种（通常是原文），系统帮忙填另外两种作参考：繁体用简繁转换，英文用机器翻译。
- 系统填的内容标“待确认”，商家首页一直有提醒，直到商家确认或改掉（问题 2：确认前要不要给顾客看）。
- 顾客看到的：简中顾客看简中，繁中顾客看繁中，英文顾客看英文，**其余 9 种语言的顾客一律看英文**；英文没有时看原文。
- 有一个特殊情况要你定：泰国的店用泰文写了店名，泰语顾客按上面的规则会看到英文名，而不是泰文原名（问题 3）。
- 地址、电话、营业时间格式不翻译。营业时间的“全天”“休息中”这些是界面文字，会跟着语言走。

## 8. 平台后台“语言适配”页（效果图 ⑦）

入口：平台后台左侧菜单“语言适配”，`/admin/i18n`。

### 8.1 看什么

- **顶部四个数字**：界面文字、系统消息、平台内容各有多少条，人工已校对的比例；以及“可能显示不下”的条数（译文比中文长很多的按钮和标签，阿拉伯文、俄语、法语最常见）。
- **左边按页面分组**：顾客（商城首页、点餐页、结算、订单、我的）、商家和员工（商家后台、后厨、员工工作台）、系统消息（短信、推送、订单通知、Excel 表头）、平台内容（商城分类、活动图、平台优惠券）。分组由文字编号的前缀决定（比如 `sf.` 是点餐页），写代码时就分好。
- **中间是表格**：编号、中文、英文、当前核对的语言、状态。筛选：全部 / 待校对 / 缺失 / 太长 / 已校对；能搜文字或编号。右上角选要核对的语言。
- **右边是页面预览**：用示例店铺打开真实页面，切到当前核对的语言；页面上能点的文字有虚线框，点一下表格就跳到那一条，正在改的那条用橙框标出来。这样能看到译文放在按钮里是否显示得下。

### 8.2 能做什么

- 点一条直接改，“保存并标记已校对”。保存后**立即生效，不用重新发版**；“恢复机器译文”撤销人工修改。
- “机器补齐缺失”：把当前语言缺的条目用设置的翻译服务补上。
- 导出 / 导入 Excel：一行一条，一列一种语言，方便找母语的人线下核对后传回。
- 每次修改记操作日志（谁、什么时候、改前改后），沿用现有的操作记录。

### 8.3 怎么做到不发版就生效

- 每种语言的界面文字是一个文件（`web/src/locales/th.json` 这样），随代码发版，是“底本”。
- 管理员在后台改的内容存在数据库 `ui_translations` 表（语言、编号、文字、状态、修改人），优先于底本。
- 浏览器加载语言包时同时取一份“后台修改”（很小，带版本号缓存），合在一起用。Go 发短信、推送时读同样的两份。
- 以后要把后台的修改并回仓库，可以导出成 JSON 文件提交。

### 8.4 菜单要不要也在这里看

商家的菜单译文由商家自己管，这一页默认不列。管理员需要时，在现有的“商品”页里能看到每道菜的多语言卡片（和商家看到的一样），可以替商家改。

## 9. 排版

### 9.1 阿拉伯文从右往左

- `<html dir="rtl">`，整页镜像：返回箭头指向右、分类栏在右边、购物车按钮在左边、抽屉从左边滑出。
- 把约 280 处写死左右的 CSS 改成“开始 / 结束”写法（`margin-inline-start`、`inset-inline-end`、`text-align: start`），这样一份样式两种方向都对。
- 有方向的图标（箭头、`›`）镜像；不镜像的：店铺 Logo、菜品图、地图、二维码、价格、手机号、订单号、英文店名。这些用 `<bdi>` 或 `dir="ltr"` 包起来，避免“₱168”被排成“168₱”。
- 数字用 0~9，不用阿拉伯–印度数字（٠١٢），中东的外卖 App 多数这样（问题 8）。
- 地图（Google Maps）自带 RTL 支持，不用改。

### 9.2 字体

- 优先用手机和电脑自带的字体。泰文、阿拉伯文、日文、繁中现代系统都自带。
- 缅甸文、高棉文的字体在部分安卓机和老电脑上缺，自带一份 Noto Sans Myanmar 和 Noto Sans Khmer（只在这两种语言时下载，各约 100~200 KB）。字体放在我们自己的服务器上，不从 Google Fonts 拉（中国大陆打不开）。
- **缅甸文编码**：缅甸以前流行 Zawgyi 编码，现在官方和主流手机都已经换成 Unicode。系统只用 Unicode；商家录入时如果检测到是 Zawgyi，提示并自动转换（用 Google 开源的 myanmar-tools 检测）。
- 泰文、缅甸文、高棉文的上下标多，行高加到 1.6~1.8 倍，避免被裁掉（效果图 ④）。

### 9.3 长度

- 法语、俄语、越南语比中文长 2~3 倍。按钮、标签允许换行；顶部标签栏、底部导航超长时缩小字号而不是截断。
- “语言适配”页的“太长”筛选用来找出显示不下的地方。

### 9.4 日期、数字、复数

- 日期时间用浏览器自带的 `Intl.DateTimeFormat` 按语言显示（泰语顾客看到泰文月份）。
- **金额格式不跟语言走，跟店铺货币走**（沿用 PR #63 的 `money()`）：同一家店给所有顾客显示一样的“₱1,234.50”，避免法语顾客看到“1 234,50 ₱”时搞不清。
- 带数量的句子（“销量 {n} 单”）支持复数写法，按 `Intl.PluralRules` 选形式，俄语、阿拉伯语会用到。

## 10. 系统消息

| 消息 | 现在 | 改后 |
|---|---|---|
| 订单状态短信 | 中文和英文两句都发 | 只发顾客的语言（没有就英文）。缅甸文、泰文、中文这些短信每段只能 70 个字符，只发一种语言能省一半短信费 |

## 14. 实现时的调整

- **第 1 批**
  - 简体中文在代码里的语言代码仍是 `zh`（和原来一样，老链接、老数据不用改），其他代码同第 3 节。
  - 第 5.2 节说“服务器读 cookie 写好 `<html lang dir>`”：线上首页由 Nginx 直接发出，Go 碰不到。改成首页 `<head>` 里一段很小的脚本，在页面画出来之前读 `?lang=`、cookie、浏览器语言，写好 `lang`、`dir`，效果一样（不闪、阿拉伯文不跳），Nginx 和 Go 两种部署都适用。
  - 原来存在浏览器 `localStorage` 里的“中文 / EN”选择，第一次打开时自动转成 cookie。
  - 界面文字：中文、英文仍写在代码里；其余 10 种语言在 `web/src/locales/<代码>.json`，只下载当前语言那一个。繁体中文由 `npm run i18n zh-Hant` 从简体自动转换（OpenCC，台湾用词）。`npm test` 会检查每种语言是否齐全、`{占位符}` 是否和英文一致，新加界面文字时要同时补上各语言。
  - 平台后台（`/admin`）里，非中英文的访问者看英文，页面方向也保持从左往右。
- **第 2 批**
  - 翻译在后台任务 `translate_menu` 里跑：商家（或平台替商家）改了菜品、分类、规格、优惠活动、Excel 导入后，几秒后整店对一遍，只翻新增和原文变了的内容；同一家店几秒内连续保存只排一个任务。每种语言一次最多 50 条。
  - 店铺“菜单原文语言”和“关掉的语言”在菜单页的“多语言”窗口里设置（不在店铺设置页）。英文不能关，因为它是兜底。
  - 菜品表单里原有的“英文名”就是商家自己的英文译文（状态“商家已改”）；在“多语言”窗口改英文菜名，也会同步回这一列，后厨、小票照旧读它。
  - 顾客端：接口按顾客语言另带 `name_tr` 等字段，原文字段不变，“查看原文”在前端切换。订单明细（外卖、自取和扫码点餐都一样）存原文和下单时顾客语言的菜名（`order_items.name_customer`），外卖订单记下顾客语言（`orders.customer_lang`）。
  - 密钥设置页新增“菜单翻译”：Claude Haiku 5.5（默认，填 Anthropic 密钥即可）、Claude Sonnet 5.5、Google 翻译，或关闭。没有翻译服务时繁体中文照样转换。
  - 这一批没做：商家优惠券名称不翻译（券面主要是“满 X 减 Y”这类界面文字，已随语言变化）；缅甸文 Zawgyi 编码检测放到第 3 批和店铺信息一起做。
