   - 会员是**按店铺**的。店员输入会员ID（也能输电话或称呼）只查本店会员，下拉选中后带出资料、地址和消费次数。
   - “新增会员”：后端按本店会员号递增发一个新号，至少 6 位（000001 起，超过 999999 自动变 7 位）。每按一次就在会员表建一条**临时会员**并占住这个号。

# 代客下单 设计方案 v0.1

顾客在微信（或电话、LINE）里把要点的菜、地址发给商家，店员在商家后台替顾客建一张外卖单。
建好后这张单和顾客自己下的单走完全一样的流程：后厨、派骑手、送达、核款、账单。

效果图：`01-pc-new-order.png`（主页面）、`02-pc-created.png`（建好后复制消息回微信）、`03-pc-orders-list.png`（订单列表的入口和标记）、`04-phone-steps.png`（手机三步）。
可点开的原型：`prototype/index.html`。

## 1. 入口和权限
- 订单页右上角“＋ 代客下单”，打开 `/merchant/orders/new`。
- 店长、经理、收银能用；后厨、骑手看不到。
- 订单列表加“全部来源 / 顾客下单 / 代客下单”筛选，代客单带“代客 · 微信”标签，写明是谁代下的。

## 2. 页面（电脑四栏，手机三步）
1. **粘贴顾客消息**（推荐做）：把微信里的整段文字粘进来点“识别”，自动填手机号、称呼、地址、菜和数量、规格、口味备注、送达时间、付款方式。菜单里没有的菜标黄提示，不会乱加。原始消息存在订单里，方便以后对账。识别用平台已经配好的 Claude 密钥（和菜单翻译同一个）；没配密钥时这块隐藏，全部手动填。
2. **顾客**：输入手机号，已注册的顾客显示“老顾客 · 下过 N 单”，列出他的常用地址可直接选；新地址在地图上定位，自动判断能不能送、配送费多少。配送 / 自取，尽快 / 预约时间。
3. **选菜**：和顾客点餐页同一份菜单，可搜索（菜名、拼音首字母、英文名），售完的菜灰掉，有规格的弹规格框。
4. **订单**：数量可加减，每道菜可写备注；费用按顾客下单同一套规则算（包装费、配送费、满减、满额免配送费）；“店家优惠”可选填，必须写原因；付款选货到付款 / 已收款（可上传微信转账截图，记为已付）/ 到店付；顾客看得到的订单备注和只有店员看得到的店内备注分开。
- 草稿自动保存，刷新或切页不会丢。

## 3. 建好之后
- 默认直接算“已接单”，不用再点接单（可以取消勾选，走正常接单）。
- 弹窗给出一段确认消息（菜、金额、地址、送达时间、订单进度链接），一键复制粘贴回微信。也可只复制链接、打印小票。
- 手机号是已注册顾客的，订单会出现在他的“订单”页；没注册的也能用链接查看进度。勾选时会发短信给顾客（需要配好短信通道）。

## 4. 数据（实现时）
- 数据库里订单表已经有 `channel = 'staff'` 这个值，一直没用上，代客单就用它。另外加：来源（微信/电话/LINE/其他）、代下店员、原始消息、店内备注、店家优惠和原因、收款截图。
- 下单接口复用顾客下单的报价和建单逻辑，只是改由店员身份调用。
