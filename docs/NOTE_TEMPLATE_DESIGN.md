## 1. 要解决什么

brian 的原话：菜单页面还需要新增口味模版。商家可以在这个页面先设置好配套的口味备注模版：

1. 奶茶类 = 微糖，少糖，少冰，去冰，热的等
2. 炒菜类 = 少油，少盐，微辣，特辣，不要葱，不要姜，不要蒜等

商家在新增菜品的时候可以使用某个模版，这样下次用户或代客下单时在选择菜品备注可以直接使用下拉模版进行单选或多选，如果还是没有符合的备注也可以自定义输入。

拆成四件事：

1. **菜单页新增“口味模板”标签**：商家建模板，模板里写好常用备注（少糖、去冰、不要葱……），定好单选还是多选。
2. **菜品套用模板**：编辑菜品时勾一个或几个模板；也能在模板页一次套给一整个分类。
3. **下单时点选**：顾客点餐页、扫码点餐、代客下单，菜品备注都变成“点选标签 + 自定义输入”。
4. **后厨、小票、订单里看得清**：点选的口味和自定义备注一起显示，后厨看商家的语言，顾客看自己的语言。

## 2. 和现有的“规格 / 加料”有什么不同

系统里已经有“规格”（菜品编辑里的选项组，如 大杯 / 中杯、加珍珠 +5），代客下单页把单选组当“规格”、多选组当“加料”。口味备注模板不是它们的替代，区别如下：

| | 规格 / 加料（已有） | 口味备注模板（新） |
|---|---|---|
| 价格 | 每个选项可以加价 | **永远不加价** |
| 必选 | 可以设必选（如杯型必须选一个） | **都不是必选**，顾客可以一个都不点 |
| 写在哪里 | 每道菜自己写一份 | **在模板里写一次**，几十道菜共用；改模板，所有套用的菜一起变 |
| 单选 / 多选 | 最少几个、最多几个 | 每组只分“单选”或“多选”，简单 |
| 自定义 | 没有 | 点选之外，**还能自己打字**（就是现在的“备注”框） |
| 售罄、库存 | 选项可售罄 | 没有售罄，只有“停用” |
| 存进订单 | 订单行的 `options`，参与算价 | 订单行的新字段 `note_tags`，不参与算价，和备注文字一起给后厨看 |

给商家的一句话说明（写在模板页和菜品编辑里）：**要加钱或必须选的，用“规格”；不加钱、可选可不选的口味要求，用“口味模板”。**

## 3. 业内怎么做

| 产品 | 做法 | 借鉴 |
|---|---|---|
| 美团外卖商家版 | 商品可加“属性”（如 甜度：全糖 / 少糖 / 无糖，温度：常温 / 去冰），属性不加价，每组单选；顾客下单时还有“备注”框和快捷标签（少辣、不要香菜） | 一组一组地分（甜度一组、温度一组），每组单选 |
| 饿了么商家版 | 商品“属性”与“规格”分开：规格能定价，属性只是做法和口味；可多选 | 规格和属性分开说明，商家不会混 |
| 收银系统（客如云、二维火、Toast） | “做法 / 口味 / 备注”预设库，菜品挂预设；服务员点菜时一点就加，也能手写；后厨单上醒目显示 | 预设库**共用**，菜品只是挂上；后厨单醒目 |

注：美团、饿了么的商家后台帮助文档不公开，这一行来自公开的商家版界面和常见用法，细节以他们后台为准。

共同点，也是本方案的做法：模板共用、按组分单选多选、不加价、点选和手写并存、后厨醒目。

## 4. 模板长什么样（效果图 01）

一个模板 = 一个名字 + 一组或几组标签。每组定单选还是多选。

例子（也是“常用模板”里自带的两个）：

| 模板 | 组 | 单选 / 多选 | 标签 |
|---|---|---|---|
| 奶茶类 | 甜度 | 单选 | 正常糖、少糖、半糖、微糖、无糖 |
| | 温度 | 单选 | 正常冰、少冰、去冰、常温、热 |
| 炒菜类 | 辣度 | 单选 | 不辣、微辣、中辣、特辣 |
| | 忌口 | 多选 | 少油、少盐、不要葱、不要姜、不要蒜、不要香菜 |

为什么要分组：brian 的例子里“微糖”和“少糖”不能同时选，“少冰”和“热的”也不能同时选，但“少糖”和“去冰”可以一起选。分成“甜度（单选）”“温度（单选）”就自然对了；“忌口”可以选好几个，就设多选。

- 只想要一串标签、不想分组的商家：新建模板时默认就是一组、多选、组名留空，直接往里加标签即可。
- 组名可以留空，留空时下单页只显示标签不显示组名。
- 每个标签最多 20 个字，每组最多 20 个标签，每个模板最多 5 组；每家店最多 50 个模板。
- 标签可以“停用”（暂时不让选，但不删），也可以拖动排序。

## 5. 商家端

### 5.1 菜单页新增“口味模板”标签（效果图 01、02）

菜单页顶部加两个标签：**菜品**（现在的页面）和 **口味模板**。权限跟“改菜单”（`menu.edit`）走；只有翻译权限的人在这里能看不能改。

- 左边：模板列表，每个显示小图标（选填，从十几个现成图标里挑）、名字、几组几个标签、**用在几道菜**。底下“+ 新建模板”和“从常用模板添加”。
- 右边：选中的模板。改名字；每组一行卡片：组名、单选 / 多选切换、标签（像输入标签一样，打字回车就加一个）、上下移、删组；“+ 加一组”。
- 右上：“套用到菜品”、“删除”。
- 删除模板：提示“正在用在 N 道菜，删除后这些菜不再显示这个模板的口味；已下的订单不受影响”。
- **从常用模板添加**：店里还没有模板时最显眼。点开是 5 个现成模板（奶茶类、咖啡类、炒菜类、粉面类、通用），勾上就加进店里，加进来以后随便改。通用 = 打包分开装、不要餐具、多给纸巾、汤和饭分开。

### 5.2 套用到菜品（效果图 03）

两个入口，结果一样：

1. **菜品编辑**（效果图 03 左）：在“供应方式”下面、“规格”上面加一栏“口味备注模板”，列出店里所有模板，可以勾一个或几个（推荐最多 3 个），下面预览顾客会看到的样子。旁边一行灰字说明和规格的区别。
2. **模板页的“套用到菜品”**（效果图 03 右）：弹窗里按分类列出所有菜，分类可整类勾选；已经套用的打勾；确认后一次保存。适合“奶茶分类 30 道菜都套奶茶类”这种情况。

菜单列表里，套了模板的菜在名字旁显示一个小标签“口味：奶茶类”，一眼看出哪些菜还没套。

### 5.3 Excel 导入导出

菜品导入表加一列 **口味模板**：填模板名字，多个用逗号隔开，如 `奶茶类，通用`。

- 名字要和店里已有的模板一模一样，对不上就整行报错“没有这个口味模板：xxx”（和现在分类对不上的处理一样）。
- 留空：新菜不套模板；已有的菜保持原样。填“无”：清空。
- 导出现有菜品时这一列填上当前套用的模板。
- 模板本身不在 Excel 里建（标签分组写进一个格子太容易写错），在模板页建，几分钟就够。
- 说明页“各列说明”和“店里现有的分类”旁边，再加一段“店里现有的口味模板”。

### 5.4 平台后台

平台后台替门店编辑菜品用的是同一个菜品编辑框，口味模板栏照样出现。后台的门店商品页（`/admin/items`）加一个“口味模板”按钮，打开和商家同样的模板编辑，方便替新店建好。

## 6. 下单时

### 6.1 顾客点餐页和扫码点餐（效果图 04）

现在：有规格的菜点“选规格”弹出面板，面板最下面一个“备注”输入框；没规格的菜点“+”直接进购物车，没地方写备注。

改成：

- 套了模板的菜，按钮和有规格的菜一样变成 **“选规格”**（没有规格只有口味时叫 **“选口味”**），点开同一个面板。
- 面板里，规格在上，下面一节 **“口味备注”**：每组一行，组名后面灰字“单选”或“可多选”，标签是小圆角块，白底细边，选中变红框金底；单选组点另一个自动换过去，再点一次取消。
- 最下面还是自定义输入框，提示语改成“其他要求，如：珍珠分开装”。
- 都不选也能直接“加入购物车”。
- 购物车、结算页、订单详情里，这一行菜名下面显示：`少糖 · 去冰 · 珍珠分开装`（点选的在前，自己写的在后）。
- 同一道菜、同样规格、同样口味和备注才合并成一行；口味不同就是两行（现在备注不同已经是两行）。
- 菜品详情页（大图那页）里，“规格”下面也列出口味选项，让顾客先看到能选什么。

扫码点餐（堂食平板，`DineMenu.vue`）用的是同一种面板，一起改。

### 6.2 代客下单（效果图 05、06）

代客下单页（`/merchant/orders/new`，深红米金 `.warm`）订单表里每行已有“备注”格。改成：

- 点备注格，格子下方弹出 **下拉面板**：顶部是输入框，下面按组列出这道菜套用的模板标签（组名 + 单选 / 多选），点一下选中、再点取消，单选组自动互斥。
- 输入框里打字会过滤标签（打“少”只剩 少糖、少冰、少油、少盐），回车选中第一个；没有匹配的，回车就当成自定义备注。
- 选好后格子里显示小块标签 + 自定义文字，例如 `[少糖][去冰] 珍珠分开装`，点格子能再改。
- 键盘：Tab 离开格子即关闭面板，Esc 关闭。
- 菜品没套模板：面板里只有输入框，和现在一样。
- 手机版（一栏布局）：点备注从底部升起同样的面板。
- 复制本行（⧉）会连口味一起复制。“再来一单”带出会员上次的单时，口味也带上（标签还在就带上，被删除或停用的转成文字）。

### 6.3 后厨、打包、小票、订单详情（效果图 07）

所有现在显示菜品备注的地方（后厨工作台、打包台、小票、商家订单列表和详情、员工工作台），统一显示成：

`口味：少糖、去冰　备注：珍珠分开装`

- 用现在备注的醒目颜色（橙色加粗），后厨一眼看到。
- 打印小票上，口味单独一行，前面加“※”。
- 后厨和小票上的口味用商家写菜单的语言（店铺的菜单语言），顾客的订单详情用顾客下单时的语言（和菜名一样，见 I18N_DESIGN 6.4）。

## 7. 多语言

- 模板的组名和标签都是商家写的文字，走现有的菜单自动翻译（`content_translations`，新增 entity `note_group`、`note_tag`），状态（机器 / 人工 / 过期）和菜品一样。
- 商家菜单页的“多语言”弹窗（`MenuTranslations.vue`）加一类“口味模板”，可以逐条改译文。
- 模板名（“奶茶类”）只给商家看，不翻译。
- 自定义备注是顾客写的，不翻译（和现在一样）；缅甸语 Zawgyi 照常自动转换。
- 常用模板的预设文字 12 种语言都准备好，加进店里时按店铺菜单语言写入，其他语言直接作为人工译文写入，省一次机器翻译。
- 界面文案（“口味备注”“单选”“可多选”“选口味”等）按现有方式加进 12 种语言的语言包。

## 8. 数据（实现时）

```sql
-- 模板
CREATE TABLE note_templates (
  id BIGSERIAL PRIMARY KEY,
  branch_id BIGINT NOT NULL REFERENCES branches(id),
  name TEXT NOT NULL,            -- 奶茶类，只给商家看
  icon TEXT NOT NULL DEFAULT '', -- 选填的小图标
  sort INT NOT NULL DEFAULT 0,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (branch_id, name)
);
-- 组：甜度（单选）、忌口（多选）
CREATE TABLE note_groups (
  id BIGSERIAL PRIMARY KEY,
  template_id BIGINT NOT NULL REFERENCES note_templates(id) ON DELETE CASCADE,
  name TEXT NOT NULL DEFAULT '',  -- 可留空
  multi BOOLEAN NOT NULL DEFAULT false,
  sort INT NOT NULL DEFAULT 0
);
-- 标签：少糖、去冰
CREATE TABLE note_tags (
  id BIGSERIAL PRIMARY KEY,
  group_id BIGINT NOT NULL REFERENCES note_groups(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  active BOOLEAN NOT NULL DEFAULT true,
  sort INT NOT NULL DEFAULT 0
);
-- 菜品套用哪些模板
CREATE TABLE menu_item_note_templates (
  item_id BIGINT NOT NULL REFERENCES menu_items(id) ON DELETE CASCADE,
  template_id BIGINT NOT NULL REFERENCES note_templates(id) ON DELETE CASCADE,
  sort INT NOT NULL DEFAULT 0,
  PRIMARY KEY (item_id, template_id)
);
-- 订单行：下单时的口味快照（之后改模板、删标签，老订单不变）
ALTER TABLE order_items ADD COLUMN note_tags JSONB NOT NULL DEFAULT '[]';
-- [{"id": 12, "group": "甜度", "name": "少糖", "name_customer": "Less sugar"}]
```

- 接口：`/merchant/branches/:bid/note-templates`（列表、新建、修改、删除），`PUT .../note-templates/:id/items`（套用到菜品，传菜品 id 列表）；平台后台同样一套挂在 `/admin/branches/:bid/` 下。菜品保存多一个 `note_template_ids`。
- 顾客菜单接口：每道菜多一个 `notes`，是它套用的模板展开后的组和标签（已按顾客语言翻译，停用的不给）。
- 下单（报价 `quote` 和代客下单）：每行多 `note_tag_ids`。服务器检查：标签属于这道菜套用的模板、没停用、单选组最多一个；不对就报错。`note` 自定义文字仍是最多 200 字。
- 购物车（`cart.ts`）行的合并键加上标签 id。
- 现有订单的 `note` 不动，老订单照常显示。

## 10. 已确认的问题（全部按推荐）

1. **模板里分组**：一个模板可以分几组，每组单选或多选（**推荐：支持分组**，像“甜度单选、温度单选、忌口多选”；新建时默认一组多选，不想分组的商家感觉不到）。
2. **一道菜能套几个模板**（**推荐：最多 3 个**，例如奶茶同时套“奶茶类”和“通用”）。
3. **口味能不能设必选**（**推荐：不能**。必须选的用“规格”，规格可以设 0 元选项；口味模板一律可选可不选，顾客不会被卡住）。
4. **没有规格只有口味的菜，点“+”要不要弹面板**（**推荐：弹**，按钮叫“选口味”，否则顾客根本看不到可选的口味；面板里不选也能直接加入）。
5. **自定义输入能不能关**（**推荐：不能关**，一直保留，200 字，和现在一样）。
6. **改模板对已经套用的菜**（**推荐：立刻全部跟着变**；已下的订单保留下单时的文字不变）。
7. **自带常用模板**（**推荐：提供 5 个**：奶茶类、咖啡类、炒菜类、粉面类、通用，一键添加后可改）。
8. **整单备注的快捷标签**（如“不要餐具”“多给纸巾”放在结算页的订单备注旁）（**推荐：这次不做**，先把菜品口味做好；“通用”模板可以先顶上）。
9. **Excel**（**推荐：只加“口味模板”一列填模板名**，模板本身在页面建）。
10. **分两批做**（**推荐：是**，第一批顾客端和后厨，第二批代客下单和导入）。
