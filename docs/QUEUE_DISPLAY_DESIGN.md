## 1. 要解决什么

brian 的原话：“堂食这边还需要新增排队页面，这个页面可以放在一个单独的屏幕上提供给客户查看（就是一个排队叫号页面）。”要两种显示模式：

1. **奶茶店模式**：顾客买完单后，在屏幕上看到“等待制作 / 正在制作 / 已做好等你来取”的订单，只显示订单号。
2. **饭店模式**：顾客手机扫码网页取号，或者找店员拿纸质号码牌；屏幕上看当前叫号和排队列表。排队按人数配桌型（4 人配 4 人桌、2 人配 2 人桌），但不是定死的：2 人等太久也可以安排到 4 人桌。店员可以插队等操作。

拆开来是三样东西：

- **一块给顾客看的屏**（电视 / 大屏 / 旧平板），只看不点。
- **一个给店员用的操作页**（门口迎宾的 iPad 或收银电脑），取号、叫号、入座、过号、插队。
- **一个给顾客用的手机网页**，扫门口二维码取号，看自己前面还有几桌，叫到时提醒。

## 2. 业内怎么做

| 系统 | 做法 | 我们借鉴什么 |
|---|---|---|
| 美团排队、海底捞、外婆家等国内连锁 | 按人数分桌型取号（常见“小桌 1–2 人、中桌 3–4 人、大桌 5 人以上”），号码带桌型字母（A012、B008）；门口大屏显示各桌型“当前叫号 / 等待桌数”，叫号时语音播报“请 A012 号到前台”；扫码排队在手机上看前面还有几桌；过号一般顺延几位或重新取号。 | 桌型字母 + 号码、大屏按桌型分栏、语音播报、过号顺延 |
| Eats365 排队叫号显示系统 | 按用餐人数设不同编码（如 1–2 人、3–6 人、7 人以上）；过号可以马上或在限定时间后从显示屏移除。 | 桌型由商家自己设人数区间；过号区停留时间 |
| Toast Tables（候位） | 店员加客人时填人数，系统按设置给出“预计等待”；桌台设最少 / 最多人数，自动推荐合适的桌；可以给候位客人先留桌；等待计时接近报价时变黄、超过变红；有手机号的客人到号时收短信。 | 预计等待用“平均翻台时间 × 前面桌数 ÷ 桌数”的简单公式；只推荐不强制；等待计时变色 |
| Yelp Waitlist、TablesReady | 顾客在网上或门口填姓名、人数、手机号加入候位；有公开的候位页面，顾客自己看排到第几；到号发短信；TablesReady 可以把候位名单投到店里的电视上。 | 公开的手机排队页；电视屏只显示号码不显示姓名 |
| 奶茶 / 快餐取餐屏（喜茶、蜜雪冰城、麦当劳、Menusifu、FreshKDS 等） | 屏幕分“制作中 / 请取餐”两栏或三栏，只显示取餐号；后厨点“完成”，号码自动跳到“请取餐”并响提示音、语音叫号；取走后号码消失。Square 自己没有顾客取餐屏，要靠第三方。 | 状态直接来自后厨屏的“开始 / 备好”，不另外让店员点 |

来源：[Toast Tables 使用说明](https://support.toasttab.com/en/article/Using-Toast-Tables-Waitlist)、[Toast Tables 顾客体验](https://support.toasttab.com/en/article/Toast-Tables-The-Guest-Experience)、[Eats365 排队叫号显示系统](https://www.eats365pos.com/tw/expansion-module/queue-display)、[Eats365 管理排队号](https://eats365pos.helpjuice.com/cmn/queuing-management/manage-queuing-tickets)、[Yelp：远程排队](https://yelp-support.force.com/article/How-can-I-use-Yelp-Waitlist-to-get-in-line-remotely?l=en_US)、[TablesReady 候位功能](https://www.tablesready.com/features/waitlist/)、[Menusifu 取餐状态屏](https://menusifu.com/zh/hardware/restaurant-order-status-screen)、[Square 社区：取餐显示屏](https://community.squareup.com/t5/Orders-Menu-Items-Catalog/Pickup-Display-Screen/m-p/710336)。美团、海底捞、客如云没找到公开的规则文档，表里国内一行是根据门店常见做法和美团排队的公开报道（[品玩](https://www.pingwest.com/w/312903)）归纳的，具体人数区间各家不同。

共同点：

- **屏幕只显示号码**，不显示姓名和手机号（隐私）。
- **系统推荐、店员拍板**：桌台匹配、升桌、插队都是店员最后决定，系统负责算“谁最该入座”和“预计等多久”。
- **叫号三件套**：大屏放大 + 提示音 / 语音 + 顾客手机提醒（短信是可选的花钱项）。

## 3. 现在系统里已经有什么

| 已有 | 在哪 | 排队叫号怎么用 |

| 菜品状态 `order_items.prep_status`、`prep_started_at`、`ready_at` | 后厨屏点“开始 / 备好” | 奶茶店三栏的来源：都没开始 = 等待制作；有一道在做 = 制作中；全部备好 = 请取餐 |

| 堂食就餐 `dining_sessions`（`guests`、开台 / 结账时间） | 堂食台面 | 入座 = 开台；空桌 = 没有打开的就餐；平均用餐时长从历史里算 |

| 门店事件流 `/merchant/branches/:id/events`、前端 `useLive` | 订单页、后厨屏 | 屏幕和操作端实时刷新 |
| 短信通知（`notify_sms`、Twilio）、浏览器推送（`webpush.ts`） | 订单状态通知 | 到号提醒 |
| 打印小票 `TicketView.vue` | 后厨、员工工作台 | 打印纸质号码条 |
| 宣传物料（图片 / 动图 / 视频轮播） | 店铺装修 → 宣传物料 | 大屏空的地方放店家的宣传图 |
| 12 种语言、`.warm` 深红米金、后台 `office.css` | 全站 | 大屏和手机页用深红米金，操作端用后台样式 |

**缺的**：排队号本身（新表）、桌型分组设置、叫号屏设备、三个新页面。奶茶店模式基本不需要新数据，只是一个新的查询和一块屏。

## 5. 奶茶店模式（效果图 01、07）

### 5.1 大屏

```
┌──────────── 河马奶茶 · 请留意您的取餐号 ───────────────── 14:32 ┐
│  等待制作 6        │  制作中 4           │  请取餐 3             │
│  041 042 043       │  037  038           │  ┌──────────┐        │
│  044 045 046       │  039  040           │  │   036    │ ← 刚做好│
│                    │                     │  └──────────┘ 放大闪烁 │
│                    │                     │  033  035             │
├─────────────── 宣传物料轮播（可关）────────────────────────────┤
```

- 三栏：**等待制作**（灰）、**制作中**（金）、**请取餐**（深红底白字，最显眼）。只显示取餐号 `pickup_code`，不显示菜名、姓名、电话。
- 号码多的时候：等待制作只显示最早的 20 个，后面写“还有 8 单”；请取餐最多 12 个，超过的按时间最早的先缩小。
- **刚做好的号**：在“请取餐”最上面放大 5 秒，响一声提示音，并用屏幕语言播报“请 036 号取餐”（第 9 节）。
- 号码什么时候出现：订单**被接单**后（先付款的店就是付完款后），出现在“等待制作”。只有不需要制作的东西（瓶装水）的单，直接进“请取餐”。
- 号码什么时候消失：店员在订单页 / 工作台 / 叫号操作端点“已取餐”；或者在“请取餐”停留超过设置的时间（推荐 15 分钟）自动从屏上撤下（订单本身状态不变）。
- 显示哪些单：推荐**自取单和堂食柜台单**；外卖单默认不显示（骑手取，不用叫号），设置里可以打开，打开后外卖单号前面加一个小摩托图标。
- 状态完全来自后厨屏，不新增“开始做”的按钮。跟烹饪进度一样：厨师跳过“开始”直接点“备好”的，号码会从“等待制作”直接跳到“请取餐”。

### 5.2 竖屏

奶茶店常把屏挂在柜台上方竖着放：上半“请取餐”大号码，下半两栏“制作中 / 等待制作”小号码，底部宣传物料（效果图 07 左）。

### 5.3 店员“取餐叫号”标签（效果图 07 右）

- 一个列表：请取餐的号码，每个号码后面“重叫”“已取餐”两个大按钮；下面是制作中、等待制作（只看）。
- 重叫：大屏再放大一次、再播报一次。
- 顾客手机上的订单页（`/o/:token`）顶部加大字“取餐号 036”和当前状态，状态变“请取餐”时手机震动（页面开着的时候）和浏览器推送。

## 6. 饭店模式：排队规则

### 6.1 桌型分组

商家把桌台按人数分成几组，每组一个字母：

| 组 | 名称（可改） | 人数 | 用哪些桌 | 默认怎么来 |
|---|---|---|---|---|
| A | 小桌 | 1–2 人 | 2 人桌 | 按现有桌台的座位数自动生成 |
| B | 中桌 | 3–4 人 | 4 人桌 | 同上 |
| C | 大桌 | 5–8 人 | 6、8 人桌 | 同上 |
| D | 包间 | 9 人以上 | 包间区域的桌 | 有“包间”区域时才生成 |

- 每组设：字母、名称（12 种语言跟店铺信息一样可以翻译）、人数区间、包括哪些桌（默认按座位数，也可以单独勾选，比如靠窗的 4 人桌只给 B 组）。
- 号码 = 字母 + 当天序号，每组每天从 001 开始：A001、B001……和取餐号分开，不冲突。
- 顾客取号只选人数，系统自动定组；选的人数没有对应组（比如 15 人），提示“请到前台找店员”。

### 6.2 预计等待

每组的预计等待 =（这一组前面还有几桌 + 1）×（这一组平均用餐时长）÷（这一组的桌数），再减去正在用餐的桌已经吃了的时间里能抵掉的部分，最后取整到 5 分钟，显示成范围“约 15–20 分钟”。

- 平均用餐时长：最近 14 天这组桌型的 `dining_sessions` 开台到结账的中位数；数据不够 20 次时用设置里的默认值（推荐 45 分钟）。
- 这个数字只是参考：大屏和手机上都写“约”，等待超过预计时间的号在操作端标黄，超过 1.5 倍标红（借鉴 Toast）。

### 6.3 空桌时推荐谁（核心）

一张桌空出来（结账关台，或者店员在桌台图上点“清台”），操作端右侧“空桌”里这张桌下面列出推荐：

1. **本组排头**：这张桌属于哪组，就推荐这组排第一个、还没过号的号。
2. **升桌建议**：如果本组现在**没人在等**，推荐**小一级组里等得最久**、并且已经等了超过“升桌等待时间”（推荐 15 分钟）的号，标“升桌”。例如 4 人桌空了，B 组没人排，A005（2 人）已经等了 22 分钟 → 推荐 A005 升到 4 人桌。
3. 本组有人在等时，**不推荐**把大桌给小组（对排着的大桌客人不公平），但店员仍然可以手动指定任何号坐任何桌（第 7.4 节）。
4. 反过来（大组的人坐小桌、拼桌、并桌）系统不推荐，都由店员手动决定。

系统**只推荐，不自动分配**。店员点推荐卡上的“叫号到这桌”，才会叫号并给这张桌留座。

### 6.4 留座

叫号时选了桌，这张桌在**堂食台面的桌台图**上显示“留座 A012”（金色），其他人开不了这张桌（店员确认后可以强开）。顾客到了点“入座”→ 自动开台，就餐人数 = 取号人数，桌台图变“用餐中”。过号或取消时留座自动解除。

### 6.5 叫号和过号

- **叫号**：大屏顶部放大“请 A012 号（2 位）到 05 号桌”或“请 A012 号到前台”，提示音 + 语音播报；顾客手机页变红、震动、推送；有手机号且店家开了短信，发一条短信。
- **重叫**：同样再来一遍，记次数。操作端显示“已叫 2 次 · 3 分钟前”。
- **过号**：叫了以后没来，店员点“过号”。推荐**不自动过号**（店员看得到人在不在门口），但叫号超过“过号提醒时间”（推荐 5 分钟）的号会标红提醒店员。
- 过号的号进大屏的“过号区”，显示 30 分钟，写“过号请到前台”。
- **过号回来**：店员点“复号”，把它插回本组**当前排头后面第 3 位**（推荐，业内常见“顺延 3 位”）；位数在设置里改。超过当天营业或店员点“作废”就不能复号了。

### 6.6 插队

- 操作端每个号都有“插队”：选“插到最前 / 插到第 N 位”，必须选原因：**会员 / 预约到店 / 老人孕妇 / 店内安排 / 其他（打字）**。
- 插队不改号码，只改顺序；大屏上的等待列表按新顺序显示。
- 每次插队写操作记录（谁、几点、从第几位到第几位、原因），在“排队记录”里能查。推荐**不要授权码**，有记录就够了；店主可以在角色权限里把“插队”只给经理。
- 店员代客取号时也可以直接“优先”（插到最前），同样要原因。

### 6.7 取消、作废、营业结束

- 顾客在手机上可以“取消排队”；店员也可以取消（电话说不来了）。
- 设置“开始取号 / 暂停取号”：暂停后手机取号页显示“暂停取号，请到前台咨询”，大屏上二维码换成这句话；已经取的号照常叫。
- 第二天号码从 001 重新开始；前一天没处理完的号自动作废。

## 7. 店员操作端（效果图 03、04）

### 7.1 布局（电脑 / iPad 横屏）

- 顶部：标题“排队叫号”，右边大按钮 **“+ 取号”**、“暂停取号”、“打开叫号屏”。
- 数字条：等待中 12 桌 · 已叫未到 2 · 今天已入座 46 · 平均等待 18 分钟。
- 左栏：桌型组（全部 / A 小桌 5 / B 中桌 4 / C 大桌 2 / D 包间 1 / 过号 3），沿用后台的 `ox-rail`。
- 中间：排队列表，每行：号码（大字）、人数、等了多久（变黄变红）、来源图标（扫码 / 纸质 / 店员）、标签（婴儿椅、轮椅、会员）、手机号后四位、状态（等待 / 已叫 2 次 / 过号）；行尾按钮：**叫号**、**入座**，更多（重叫、过号、复号、插队、取消、改人数）。
- 右栏：**空桌和快空的桌**。空桌卡片下面是推荐的号（第 6.3 节），一键“叫号到这桌”；“快空的桌”是已经结账中 / 用餐超过平均时长的桌，只是提示。

2. **排队中 `/q/t/:token`**：大号码 B013、桌型和人数、“前面还有 3 桌”、预计等待、进度条；当前叫到 B010；按钮“先看看菜单”（打开点餐页，只看不点）、“取消排队”；“打开提醒”（浏览器推送）。

## 9. 叫号屏（效果图 01、02）

### 9.1 接入

照抄“绑定平板”：

1. 商家后台 → 排队叫号 → 设置 → **叫号屏** → “添加屏幕”，起名（如“门口电视”），选**模式**（奶茶店 / 饭店）、**方向**（横 / 竖）、**语言**，得到 6 位配对码（10 分钟有效）。
2. 电视的浏览器打开 `order.域名/screen`，输入配对码，之后一直保持登录（长期令牌，只能读这家店的排队数据）。
3. 设置里能看到每块屏最后在线时间，可以“解除绑定”。

一家店可以有多块屏（门口一块饭店模式，取餐台一块奶茶店模式）。

### 9.2 饭店模式大屏布局（效果图 02，1920×1080）

- 顶部深红七宝纹条：店铺头像 + 店名 + 时间。
- 左大块：**正在叫号**，最近一个号特大显示“A012 · 请到 05 号桌”，下面是最近 3 次叫号。
- 右上：**各桌型**一行一组：桌型（A 小桌 1–2 人）、当前叫到、等待几桌、预计等待。
- 右中：**等待号码**：每组前 8 个号码，插队的照新顺序。
- 右下：**过号区**（过号请到前台）。
- 底部左：**扫码取号**二维码 + “暂停取号”时换成提示；底部右：宣传物料轮播（可关）。

### 9.3 声音和语言

- 提示音 + 语音播报用浏览器自带的语音合成（`speechSynthesis`），说屏幕设置的语言，如“请 A012 号顾客到 05 号桌”。
- 风险：有些电视盒子的浏览器没有中文 / 缅甸语等语音，这时只响提示音；设置页有“试播”按钮，装屏时先试。
- 浏览器要求先点一下页面才能出声，所以配对完成那一下点击就把声音打开；屏幕右下角有小喇叭图标显示声音是否已打开。
- 屏幕文字只显示设置的那一种语言（跟后台一致，不双语）；可选“第二语言”，开了以后固定的标题（如“请取餐 Ready”）下面加一行小字，号码不受影响。
- 防烧屏 / 不黑屏：页面申请屏幕常亮（Wake Lock）；断网时右上角显示“连接中断”，恢复后自动刷新。

## 10. 权限

沿用角色权限表（STAFF_ACCESS_DESIGN），加三行：

| 权限 | 能做什么 | 店主 | 经理 | 接单员 |
|---|---|---|---|---|
| `queue.use` | 看排队、取号、叫号、入座、过号、复号、取消；取餐叫号的重叫 / 已取 | ✓ | ✓（默认开） | ✓（默认开） |

## 11. 不做（这一版）

- **线上预约订座**（订几点的座位）：和排队是两回事，以后单独做；预约的客人到店后店员用“插队 → 预约到店”处理。
- **排队时先点菜**：顾客页只能看菜单；以后可以接到“入座后自动带入购物车”。
- **排队收费 / 押金、排队优惠券**（如“等太久送小菜”）：不做，涉及金额要走验算流程。
- **自动并桌 / 拼桌推荐**：由店员手动。
- **取号机（自助打印机立式终端）**：iPad 打开店员取号页的“自助模式”可以以后加，这版不做。
- **平台后台**：不加页面，平台“只读进入门店”能看到。
