brian 的要求：给所有员工和订单加“班次”。店主可以给整个店设班次时间，例如早班 08:00–17:00、中班 17:00–次日 00:00、晚班 00:00–08:00，或者早班 09:00–21:00、晚班 21:00–次日 09:00，时间由店主自己定。班次功能默认关闭，店主手动开启。财务里能看每个班次的销售等数据。

## 1. 一句话方案

1. **班次是“时间段”**：店主在“设置 → 班次”里把一天切成几段，每段起个名字。系统按时间自动把订单、收款、退款、考勤归到班次，**店员不用做任何操作**，不用点“开班”“交班”。
2. **默认关闭**。不开启，系统和现在完全一样。开启、关闭、改时间都不改任何订单的金额。
3. **班次可以跨午夜**。第 1 个班的开始时间就是“班次日”的开始：三班制从 08:00 到第二天 08:00 算同一天，凌晨的晚班算前一天的。
4. **财务加一页“班次报表”**：一天里各班并排比（单数、销售额、各付款方式收款、退款、优惠、当班员工），可以点进一个班看明细，也可以看一段时间里各班的对比。
5. **改班次时间只影响以后**：新时间从下一个班次日生效，历史订单和报表仍按当时的班次，不会变。
6. **交班点钞做成可选**：每个班结束时可以点一次钱箱，系统算应有多少、差多少。只是记录，不锁账、不动余额。
7. 订单列表、考勤、工作汇总都多一个班次标记和筛选。

## 2. 业内做法调研

2026-11-28 查的公开资料，来源列在本节末尾。没查到官方说明的直接写“没查到”。

业内说的“班次”其实是两种不同的东西，先分清楚：

- **甲：时间段型**。老板在后台定好几个时间段，系统按时间自动分，报表可以按时间段看。店员没有任何操作。
- **乙：交接班型**。收银员上班时“开班”，下班时点“交班”，班次就是从开班到交班这一段。交班时点钱箱、打印交班单，之后这个班的账就锁了。

| 产品 | 类型 | 做法 | 对我们有用的地方 |
|---|---|---|---|
| **Square**（Reporting hours） | 甲 | 后台可以建多组自定义时间段，各有名字、开始和结束时间，报表按它筛选。跨夜的时间段，**按开始时间决定算哪一天**。 | 和 brian 要的最像：老板定时间，报表按它分。跨夜归到开始那天，我们照这个思路。 |
| **Square for Restaurants**（Shift report、Close of day） | 乙 | 每个员工下班前跑自己的班次报告（应交店里的现金、销售汇总）；钱箱单独“结束钱箱”出报告；经理最后跑“日结”。日结要求哪些步骤可以由老板配置。 | 现金清点是和钱箱绑在一起的，和销售报表分开。 |
| **Toast**（Closeout hour、Service Report、Shift Review） | 甲 + 乙 | 营业日切换时间默认凌晨 4 点，可设在 0 点到中午之间。Service Report 把日结报表按“服务时段”（早市、午市、晚市）拆开，时段在营业时间里配置。Shift Review 是员工下班前的可选步骤，现金差额超过后台设的阈值要经理批准。24 小时营业的店，官方建议把营业日切换定在最闲的时候，并在切换前做完交班。 | 营业日切换时间和时段报表是两个设置。交班是可选的。现金差额阈值值得以后做。 |
| **Lightspeed Restaurant**（X / Z report） | 乙 | X 报告是班末报告，不清零；Z 报告是日结，清零。K 系列里一个班次报告下面挂着每个员工和每个钱箱的报告。钱箱报告有开班金额、应有现金、实点金额。 | “一个班下面看每个人”的层级，我们的班次明细页照这个排。 |
| **Eats365** | 乙 | 要先“开班”才能收款，“关班”后这台机器不能再收款；还有班没关时不能日结。 | 强制交班会挡住收款，对小店是负担。 |
| **美团收银** | 乙 | 首页点“交班”，核对交班时间、人数、订单数后开始交班，打印交班单，未结账的单不算。**交班后已结账的订单不能再退单和反结账**。交班旁边有“日结”。官方问答里提到交班记录只能查 7 天。 | 交班后锁账很严格，但会挡住售后，我们已经有按商品退款，不能照搬。 |
| **银豹收银** | 乙 | 没有“不用交班”的模式，退出软件就要交接班；可以开“盲交”（交班时不让收银员看到应有金额）；可以让收银员登录时输入备用金；后台有交接班记录。 | 盲交和备用金是常见选项，列进待定问题。 |
| **客如云、二维火、哗啦啦** | — | 没查到官方的班次或交接班说明。 | 不下结论。 |

从这些产品里看到的共同点：

1. **看销售用时间段，管现金用交接班，是两件事。** brian 说的是“店主设时间、财务看每个班的销售”，是甲。所以主体做甲。
2. **跨夜靠两条规则解决**：一天从哪个时间开始（Toast 的营业日切换时间），跨夜的班算开始那天（Square）。
3. **强制交班是负担。** 国内收银软件强制交班、交班后锁账，适合一台收银机一个收银员的店。我们的店多台设备同时用、顾客自己下单、骑手收现金，硬套会挡住正常收款和售后。Toast 把交班做成可选，我们也做成可选。
4. **现金清点都跟着班次走**，内容都是“应有、实点、差额”三个数。我们对账页已经有每天一次的钱箱点钞，改成可以每班点一次即可。

## 3. 现在系统里有什么

| 已有的 | 现状 | 和班次的关系 |
|---|---|---|
| 门店时区 `branches.timezone` | 所有“按天”的统计都按门店时区 | 班次时间也按它 |
| 每日重置时间 `branches.day_reset_time`（默认 04:00）和 `orders.biz_date` | 只用来给取餐号、订单号清零 | 不动。见 5.3 |
| 对账页 | 按**收款时间**、自然日（00:00 到 24:00）汇总各付款方式；可按品牌看 | 不动。班次报表的收款部分用同一套口径，只是换了分段 |
| 账单页 | 按**下单时间**、自然日 | 不动。班次报表的销售部分用同一套口径 |
| 钱箱点钞 `cash_counts` | 每天一次，应有 = 店里收的现金 + 骑手交回的现金 | 开启班次后可以每班点一次 |
| 考勤 `staff_shifts` | 一条记录是一个人从上班到下班 | 用它算“当班员工”。**代码里这张表叫 shift，和这次的“班次”不是一回事**，新表另起名字（见第 9 节） |
| 订单上的人 | `placed_by` 下单人、结账人、每件商品谁做的、哪个骑手送的 | 班次明细里按人汇总 |
| 一店多品牌 | 对账、账单可以全店看也可以按品牌看 | 班次是全店一套，报表可以按品牌筛 |

## 4. 设置班次

位置：**设置 → 班次**（新标签）。只有店主能开关和改时间（待定 Q10）。

- 一个开关，默认关。
- 开启后设 2 到 6 个班，每个班有名字、开始时间、结束时间、颜色。结束时间小于等于开始时间表示到第二天。
- 给两个现成的模板：两班（09:00–21:00 / 21:00–次日 09:00）、三班（08:00–17:00 / 17:00–00:00 / 00:00–08:00），点一下填好再改。
- 页面上有一条 24 小时的时间条，改时间时跟着变，一眼看出有没有重叠、有没有空档。
- 校验：
  - **不能重叠**，重叠不让保存。
  - 所有班加起来不能超过 24 小时。
  - **可以有空档**（例如店只开 10:00–22:00）。空档时间的订单和收款记在“班次外”，报表里单独一行，合计不会少（待定 Q3）。
- 班次名字是店里自己人看的，不做多语言翻译，商家写什么就显示什么。
- 时间精确到分钟，建议按整点或半点填。

### 4.1 班次日

**第 1 个班的开始时间就是班次日的开始。** 从这个时间到第二天同一时间是一个班次日，里面所有的班都算这一天的。

| 设置 | 班次日 11-27 的范围 | 各班 |
|---|---|---|
| 早 08:00–17:00、中 17:00–00:00、晚 00:00–08:00 | 11-27 08:00 至 11-28 08:00 | 晚班是 11-28 00:00–08:00，算 11-27 的 |
| 早 09:00–21:00、晚 21:00–09:00 | 11-27 09:00 至 11-28 09:00 | 晚班是 11-27 21:00 至 11-28 09:00 |

如果店主希望凌晨的晚班算在当天最前面（晚班 00:00–08:00 是 11-27 的第一个班），把晚班拖到第 1 位就行，班次日就变成 00:00 开始。

## 5. 归属规则

### 5.1 什么东西按什么时间归班

| 数据 | 按什么时间 | 说明 |
|---|---|---|
| 订单（单数、销售额、优惠） | **下单时间** | 和账单页一样。预约单也按下单时间 |
| 加单 | 仍算原订单的班 | 一张单只属于一个班，不拆 |
| 收款（现金、在线、储值、平台） | **收到钱的时间** | 和对账页一样。后补的现金（`topup_cash`、`late_cash`）按补收的时间 |
| 退款 | 退款的时间 | 和对账页一样。明细里注明原订单是哪个班的 |
| 骑手交回的现金 | 交回的时间 | 进那个班的钱箱应有 |
| 储值充值 | 充值的时间 | 进那个班的现金或在线收款，和对账页的储值块一致 |
| 考勤 | 上班到下班这一段和哪些班重叠 | 一条记录跨两个班时两个都标，各算各的时长。重叠不到 15 分钟的不标（提前几分钟到岗不算上了前一个班） |
| 做好的商品、送达的单 | 做好、送达的时间 | 班次明细里“当班员工”的数字 |

销售按下单时间、收款按收款时间，是两个口径，所以同一个班的“销售额”和“收款合计”可以不一样。例如 16:50 下单、17:10 结账的堂食单，销售算早班，收款算中班。报表上两块分开标清楚（待定 Q1）。

**不变的规则：各班（加上“班次外”）相加，等于这个班次日的合计。** 销售、每种付款方式、退款、优惠都是这样。实现时用测试守住。

### 5.2 员工怎么算“属于哪个班”

不做排班。员工属于哪个班，**看考勤**：这个班的时间里上过班的人就是当班员工。这样不用店主每天排班，换班、顶班也不用改设置。

没开店内考勤（没人打上下班）的店，“当班员工”改按“这个班里有过操作的人”列出（下过单、收过银、做好过商品、送过单）。

要不要做真正的排班（提前安排谁上哪个班、迟到早退），见待定 Q7，推荐这次不做。

### 5.3 和现有“营业日”的关系

系统里现在有三种“一天”，这次再加一种，各管各的：

| 哪种“天” | 从几点开始 | 用在哪 | 这次动不动 |
|---|---|---|---|
| 自然日 | 00:00 | 对账页、账单页、核款 | 不动 |
| 营业日（每日重置时间） | 默认 04:00 | 取餐号、订单号清零 | 不动 |
| **班次日** | 第 1 个班的开始时间 | 班次报表、订单列表的班次筛选 | 新增 |

因为范围不同，**班次报表某一天的合计和对账页同一天的合计可以不一样**（班次日 11-27 是 08:00 到次日 08:00，对账页 11-27 是 00:00 到 24:00）。班次报表上始终写明这一天的起止时间，避免误会。同一段时间内两边口径一致，能对得上。

推荐先不把对账页和账单页改成按班次日（待定 Q2）。原因：对账页和余额、平台结算、月结账单的日期连在一起，改了影响面大；先让班次报表独立运行，用顺了再决定。

### 5.4 改班次时间对历史的影响

- 每次保存班次设置都存成一个**新版本**，带生效日期。旧版本不删。
- **新时间从下一个班次日生效**。今天和以前的订单、报表一律按当时的版本算，不会因为改了设置而变。
- 保存前弹窗写清楚：从哪天几点生效、正在进行的班怎么办（按原时间结束）。
- 新旧版本的班次日开始时间不同时，交接那天中间会多出或少掉一段（例如旧的到 08:00 结束、新的 09:00 开始，中间一小时），这一段记“班次外”，不丢数据。
- **开启**：从开启当天的班次日起有班次数据，之前的日子在班次报表里显示“这天还没有开启班次”。不回头给老订单补班次（待定 Q5）。
- **关闭**：以后的订单不再分班，报表入口保留，历史照常能看。
- 订单下单时把班次（班次日、班次名）记在订单上作为快照，订单列表筛选用它；收款、退款按时间对照当时的版本计算。

### 5.5 交班点钞（可选）

现在对账页每天可以点一次钱箱。开启班次后，改成**每个班可以点一次**：

- 入口：班次明细页的“交班点钞”，以及工作台里（班快结束时）。
- 系统给出这个班的钱箱应有 = 这个班店里收的现金 + 这个班骑手交回的现金 − 这个班的现金退款，店员填实点金额和备注，系统算差额。
- **不强制**。不点也能继续收款，不锁账，不影响售后。没点的班在报表里显示“还没点”。
- 只是一条记录，不改订单、不动余额。保存后店主或经理可以更正，更正留记录。
- 对账页全天的钱箱那一块，显示当天各班点钞的合计。

这次不做的：开班备用金、盲交（点钞时不显示应有金额）、差额超过阈值要经理批准、打印交班单、交班后锁账。都列在待定 Q8、Q9。

## 6. 财务 → 班次报表

位置：**财务 → 班次报表**（新标签，开启班次后才出现）。权限跟对账页走（有对账权限的人能看）。可以选全店或某个品牌，可以导出 Excel。

### 6.1 按天（[04](shift-screens/04-report-day.png)）

选一个班次日，各班并排：

- 顶部每个班一张卡片：销售额、单数、客单价、当班人数、占全天的比例。
- 下面一张表，列是各班和全天合计，行是：
  - 销售（按下单时间）：订单数、销售额、优惠合计
  - 收款（按收到钱的时间）：现金、在线支付、储值余额、外卖平台、收款合计
  - 退款、净收款
  - 交班点钞状态

### 6.2 一个班的明细（[05](shift-screens/05-shift-detail.png)）

- 销售：单数、销售额、客单价、优惠，按订单类型（堂食、代客下单、商城、网店、外卖平台）分。
- 收款：按付款方式（在线支付细到 GCash、Maya 等）的笔数和金额，退款，净收款。
- 钱箱：应有、实点、差额。
- 当班员工：每人的上下班时间，下了几单、收了几笔、做好几件商品、送达几单。
- 可以点进订单列表看这个班的所有订单。

### 6.3 按时间段（[07](shift-screens/07-report-range.png)）

期间如果改过班次设置，按班次名字合并；名字不同的班各列各的。

## 9. 数据设计（给实现用）

现有的 `staff_shifts` 是考勤，这次不改名，新表用 `work_shift` 前缀避开。

- `branches.work_shifts_on BOOLEAN NOT NULL DEFAULT false`
- `work_shift_plans`：一次保存一个版本。`id, branch_id, effective_day DATE`（从哪个班次日生效）、`day_start_min`（班次日开始，分钟）、`created_by, created_at`。
- `work_shift_defs`：版本里的每个班。`plan_id, seq, name, color, start_min, end_min`。
- 数据库函数 `work_shift_at(branch_id, 时间)`：返回班次日、班次（或“班次外”）。所有归班都走这一个函数，避免各处各算各的。
- `orders.shift_day DATE, shift_def_id BIGINT`：下单时的快照，可空（没开启时为空）。
- `cash_counts` 加 `shift_def_id`（可空，空表示全天那一次），主键改成 `(branch_id, day, shift_def_id)`；点钞更正写审计日志。
- 报表查询：销售按 `orders.shift_*`，收款、退款、骑手交回、储值按时间调 `work_shift_at`。

## 10. 金额和余额验算的影响

这次只有文档，没有改代码，不需要跑验算。实现时：

**金额（docs/PRICING_CHECK.md）**：班次报表是对账、账单这一类，属于铁规则范围。

- 不改计价引擎，不新写金额计算。报表里的金额只读订单已有的快照和金额流水，和对账页、账单页用同一套查询口径。
- 要加的验算：真库场景测试，建跨午夜、跨班收款、加单、退货、按商品退款、储值支付的订单，每步 `checked`，再断言“各班（含班次外）相加 = 同一时间范围的对账页和账单页数字”，每种付款方式、退款、优惠各断言一次。手算样例写进 PRICING_CHECK.md 第 4 节。
- `make pricing-check` 全过，PR 写“金额验算”一节。

**余额（docs/BALANCE_CHECK.md）**：

- 班次报表里会显示储值余额支付、充值、退到余额，这些是**只读**账本数据。不新增凭证种类，不记新账，不动 `wallet_post_journal`。
- 交班点钞是钱箱现金的记录（`cash_counts`），不是余额账本，不记账。
- 因为报表读了余额数据，实现 PR 仍然跑 `make balance-check`，并断言“各班的储值收支相加 = 对账页储值块”，PR 写“余额验算”一节说明没有改记账。

如果验算时发现现有对账或账单的数字本身对不上，先停下告诉 brian，不改断言去凑。

## 12. 需要 brian 决定的问题

| # | 问题 | 推荐 |
|---|---|---|
| Q1 | 订单算哪个班？16:50 下单、17:10 结账的单，算早班还是中班 | **销售按下单时间（算早班），收款按收到钱的时间（算中班），报表里两块分开显示。** 和现在账单页、对账页的口径一致，各班相加能和这两页对上。另一种做法是全部按结账时间，简单但“早班接了多少单”就看不准了 |
| Q2 | 开启班次后，对账页和账单页的“一天”要不要也改成班次日（如 08:00 到次日 08:00） | **先不改**，只有班次报表按班次日。对账页连着余额、平台结算和月结账单，改动面大；班次报表上会写明每天的起止时间 |
| Q3 | 班次要不要必须排满 24 小时 | **不要求**。可以有空档，空档里的订单记“班次外”单独一行。不许重叠 |
| Q4 | 改班次时间什么时候生效，历史要不要跟着变 | **从下一个班次日生效，历史不变** |
| Q5 | 开启班次时，要不要给以前的老订单补上班次 | **不补**，从开启那天起才有。老订单当时没有班次，补了等于改历史 |
| Q6 | 凌晨 00:00–08:00 的晚班算前一天还是当天 | **由店主排的顺序决定**：第 1 个班的开始时间是一天的开始。按 brian 例子的顺序（早、中、晚），晚班算前一天的最后一个班 |
| Q7 | 员工归班次，要不要做排班（提前安排谁上哪个班，算迟到早退） | **这次不做**，按考勤自动算谁在哪个班上过班。排班是另一块功能，需要的话单独出方案 |
| Q8 | 交班点钞做不做，要不要强制 | **做，可选，不强制，不锁账**。强制交班会挡住收款和售后 |
| Q9 | 点钞要不要做备用金、盲交、差额超过多少要经理批准、打印交班单 | **第一版都不做**。用起来后需要哪个再加，推荐顺序：备用金、交班单、差额阈值、盲交 |
| Q10 | 谁能开关和改班次 | **只有店主**。经理能看报表和点钞，不能改时间 |
| Q11 | 班次是全店一套，还是每个品牌各设各的 | **全店一套**。班次是人和时间的事，同一批员工同时做几个品牌。报表可以按品牌筛 |
| Q12 | 最多几个班，要不要按星期几设不同班次（如周末多一个班） | **最多 6 个，每天一样**。按星期几不同第一版不做 |
