## 0. 结论先看

1. **充值送 = 顾客先付钱给门店，门店送一笔赠送金。** 钱由门店收（到店现金或扫码，店员确认），平台不经手，和现在“货到付款、到店付款”一样。
2. **储值余额分两本账：本金和赠送金。** 本金是顾客自己的钱，赠送金是门店的营销让利。两本账分开记，才能说清楚退款先扣谁、能不能退、营业额怎么算。沿用店铺余额已经做好的复式记账（`wallet_*` 表），只加账户种类。
3. **消费时按比例扣**（推荐，Q2）：余额 1000 本金 + 200 赠送，花 300 就扣 250 本金 + 50 赠送。零头永远让“可退的本金”少不多。
4. **储值是付款方式，不是优惠**：和店铺余额一样，订单金额、满减门槛、券、税一行不动，计价引擎不改。账单里单列“储值赠送抵扣”，商家看得到营销成本。
5. **储值只在这一家门店用**（门店下所有品牌通用，和店铺余额一致），**不能转给别人、不能提现**；本金能按规则退（Q3），本金**永不过期**（菲律宾《礼品券法》禁止储值过期）。
6. **合规**：只在一家商家用的闭环储值，在菲律宾、新加坡、马来西亚都在电子货币牌照的豁免范围内（第 2.3 节）。平台按国家开关、设余额上限，商家开通时同意储值条款。不是法律意见，正式上线前建议请当地律师看一下条款。
7. **页面**：商家后台左侧新加“营销”分组（营销活动 = 充值送，优惠活动 = 原来的“优惠”）；点单下加“会员充值”收银台；财务“店铺余额”加“储值”标签。顾客端新加店铺“优惠活动”页（储值卡、充值档位、可领的券、满减和菜品活动），店铺页、品牌页、结算页都有入口。
8. **分三批做**，每批都按 PRICING_CHECK.md 验算（第 11 节已写好新增规则和手算样例）。

## 2. 业内怎么做（调研）

### 2.1 国内餐饮收银和平台

| 做法 | 常见规则 | 我们借鉴什么 |
|---|---|---|
| 收银系统会员储值（客如云、美团收银、二维火、哗啦啦等） | 档位“充 X 送 Y”，送金额或送券；消费时扣款顺序常给几种让商家选（按比例 / 先本金 / 先赠送）；赠送金可设有效期；储值只在本店或连锁内通用 | 档位 + 送金额或送券；**本金、赠送分开记**；扣款顺序我们只做一种（按比例，Q2），减少商家误设 |
| 美团、饿了么平台上的“商家储值卡/会员卡” | 在平台下单时用商家储值抵扣；储值钱由平台代收再结算给商家 | 我们没有线上支付，钱由门店直接收，平台不代收（降低平台的合规负担） |
| 退卡纠纷和法院判例 | 法院支持顾客退卡；**顾客原因退卡**，商家可以把已经享受的赠送扣回（按原价重算已消费的）；**商家原因**（闭店、换老板），按实付和赠送的比例退，不能扣赠送；“不退赠送部分”的条款常被认为无效 | 退储值规则（Q3）：顾客原因扣回已用赠送，门店原因全退剩余本金；赠送金本身不退现金 |
| 闭店跑路 | 多地对单用途预付卡要求备案、预收资金存管；大量投诉来自闭店后储值无法退 | 平台显示每家门店“欠顾客多少储值”，设余额上限，停业时冻结和处理（第 9 节） |

### 2.2 海外

| 做法 | 规则 | 我们借鉴什么 |
|---|---|---|
| 星巴克储值卡（各国条款） | 卡内金额不能换现金、多数国家不退；奖励（星星）按活动另算，没有现金价值 | 赠送金不能换现金；本金在菲律宾等地不能设过期 |
| Grab、foodpanda 钱包 | 平台钱包，要电子货币牌照，余额有上限，超限部分原路退回 | 我们不做平台钱包；按门店储值、设上限 |
| 海外华人餐厅常见做法 | 纸质/实体储值卡、Excel 记账，“充 500 送 50”；常见纠纷是记账对不上、员工私改余额 | 复式记账、只追加流水、店员改不了余额、顾客每笔都收到通知 |

### 2.3 合规（公开资料整理，不是法律意见）

| 国家 | 规定 | 对门店储值的意思 |
|---|---|---|
| 菲律宾 | BSP Circular 1166（2023，取代 649）：只由“商家兼发行人”自己收的**闭环**钱包不按电子货币管。RA 10962《礼品券法》（2017）：礼品券/礼品卡（含代码、电子形式）**不能设过期**、不能拒绝兑付余额，违反罚 50 万–100 万比索；促销赠送（DTI 认定的会员、奖励、促销计划）和优惠券不在此列 | 门店储值是闭环，不需要牌照；**本金不能过期**；赠送金属于促销，可以设有效期但我们首版也不设（Q4） |
| 新加坡 | 《支付服务法》2019：只用于“有限用途电子货币”（预付卡、限定商品/服务）的服务不受监管 | 单店储值属于有限用途，不需要牌照 |
| 马来西亚 | BNM《有限用途电子货币豁免令》2024（P.U.(A) 463/2024）：购买商品/服务、存奖励、退款、电信四类可豁免，要满足豁免令第 4 段的条件；2025 年起不再适用电子货币政策文件 | 单店储值属于“购买商品/服务”类，**具体条件（如余额上限）开通马来西亚前要请律师核对** |
| 中国大陆 | 单用途商业预付卡由商务部门管：发卡备案、预收资金超过一定比例要存管；多用途要支付牌照 | 我们目前不面向大陆；如果以后有，按国家开关默认关 |

结论：

- **只在一家门店用、不能转、不能提现、钱由门店自己收**——这是最安全的形态，三个主要市场都不需要牌照。
- 平台要做的：按国家开关、余额上限、商家同意条款、顾客充值前看到条款、门店停业有处理流程。
- 跨门店通用（连锁储值）、平台代收钱、平台钱包都会接近电子货币，本方案都不做。

## 3. 储值是什么

| | 储值（本方案新加） | 店铺余额（已有，退款存入） |
|---|---|---|
| 钱从哪来 | 顾客到店付钱充值 + 门店赠送 | 门店把订单退款存进来 |
| 账户 | 顾客 × 门店，分**本金**、**赠送金**两个账户 | 顾客 × 门店，一个账户 |
| 能在哪用 | 这一家门店的所有品牌，堂食、外卖、自取 | 同左 |
| 平台单（Grab 等） | 不能用 | 不能用 |
| 能不能退现金 | 本金可以按规则退（Q3）；赠送金不能 | 不能 |
| 过期 | 本金永不过期；赠送金首版也不过期（Q4） | 不过期 |
| 转给别人、换币种 | 不行 | 不行 |
| 钱是谁的 | 门店预收的，门店欠顾客 | 门店欠顾客 |

## 4. 商家设置充值送活动（营销活动页）

### 4.1 页面位置

左侧菜单新加“**营销**”分组（Q10）：

- **营销活动**（新，`/merchant/marketing`）：充值送活动、储值概况、顾客活动页预览。
- **优惠活动**（就是现在的“优惠”`/merchant/promos`，外卖活动 / 堂食活动 / 优惠券三个标签不变，只是挪进分组）。

点单分组下加“**会员充值**”（`/merchant/order/topup`），给收银员用。财务“店铺余额”页加“储值”标签。

### 4.2 营销活动页内容（效果图 01、02）

顶部四个数（按门店，多品牌时可按品牌筛来源）：

| 数 | 说明 |
|---|---|
| 储值余额（欠顾客） | 所有顾客本金 + 赠送金之和；本金单独显示 |
| 本月充值 | 本月实收本金合计、送出赠送金合计 |
| 本月消费 | 本月用储值付的金额（其中本金、赠送各多少） |
| 储值顾客数 | 有储值余额的顾客数 |

下面是活动列表，每个活动一张卡：名称、档位（充 500 送 50 / 充 1000 送 150 …）、生效时间、状态（进行中 / 未开始 / 已结束 / 已停用）、已参与人次、充值合计。

### 4.3 一个活动能设什么（效果图 02）

| 项 | 说明 |
|---|---|
| 名称 | 例如“周年庆充值送”，多语言跟菜单一样自动翻译 |
| 档位（1–6 个） | 每档：充值金额、送赠送金（可 0）、附送券（可选，选一条已有的券规则，Q1）、档位标签（“最受欢迎”） |
| 自定义金额 | 开关：顾客可以充任意金额（最低 X），**不送** |
| 生效时间 | 开始、结束（不填 = 一直有效） |
| 每人限次 | 每档每人最多参加几次（不填 = 不限）；可勾“首次充值专享” |
| 总名额 | 每档最多多少人次（不填 = 不限） |
| 适用品牌 | 多品牌门店：在哪些品牌的页面展示（储值本身全门店通用） |
| 充值方式 | 到店现金、到店扫码（取门店已开通的付款方式） |
| 规则说明 | 系统按设置自动生成（本金不过期、赠送不退现金、只在本店用、退款规则），商家可以补充，不能删系统那几条 |

规则：

- 同一时间每家门店最多一个“进行中”的充值送活动（避免顾客看到两套档位不知道选哪个）。
- 活动改档位只影响以后的充值；已经付了的充值单按下单时的档位快照入账。
- 门店第一次开活动时要同意《商家储值条款》（第 2.3 节的要点：门店是发行人、钱由门店收、门店负责兑付和退款、停业要先处理储值）。
- 国家没开通储值（平台开关）的门店看不到这个功能。

## 5. 顾客端店铺“优惠活动”页（效果图 05–08）

### 5.1 网址和入口

- 商城：`/mall/s/:slug/offers`；店铺/品牌专属页面：`/offers`。
- 入口：店铺页店铺卡下的“优惠”条（显示“充500送50 · 2 张券可领”，点开进页面）；“我的 → 店铺余额”里每家门店的卡片上“去充值”；结算页付款方式卡里“储值不够？充值更划算”。

### 5.2 页面内容（从上到下）

1. **本店储值卡**（登录了才显示）：本店余额（本金 + 赠送 + 退款余额，Q6）、“明细”链接；没登录显示“登录后查看余额”。
2. **充值送**：档位卡片（充 ¥ / 送 ¥ / 附送券），选中一档，下面“立即充值”。显示规则说明（可展开）。
3. **可领优惠券**：店铺领券（现有 `StoreCoupons` 的内容，改成整行大券样式），已领的显示“已领取”。复购礼券、新人券如果这家店有，也写一行说明“下单后送 XX 券”。
4. **店铺活动**：生效中的满减、折扣、指定菜品活动、第二份半价，标上“外卖 / 堂食 / 自取”和时间段；指定菜品活动可以点“去看看”跳到菜。
5. 底部：“去点餐”按钮。

页面用顾客端深红米金（`.warm`），字号按 customer-warm-theme 的层级；电脑版两栏（左：储值卡 + 充值，右：券 + 活动）。

### 5.3 顾客充值流程（效果图 06）

没有线上支付，所以顾客在手机上“下充值单”，到店付钱：

1. 选档位 → 勾选同意《储值规则》→ “生成充值码”。
2. 系统建一张**充值单**（待付款，30 分钟有效），显示二维码和 6 位充值码，“请到店出示给店员”。
3. 店员在“会员充值”扫码或输码，看到顾客和档位，收钱，选收款方式（现金 / GCash…），点“确认收款”。
4. 顾客手机上自动变成“充值成功：本金 500.00 + 赠送 50.00”，收到站内消息。

外卖顾客不在店里怎么办：首版**不支持骑手代收充值**（骑手收钱是另一套风控，Q7）。

## 6. 收钱：店员确认充值（会员充值页，效果图 03）

两种开始方式：

| 方式 | 流程 | 防什么 |
|---|---|---|
| 顾客出示充值码 | 店员扫码/输码 → 核对档位 → 收款 → 确认 | 顾客本人发起，店员不能改档位和金额 |
| 店员直接给顾客充 | 输手机号或会员号 → 选档位 → 收款方式 → 给顾客手机发短信验证码，顾客报码 → 确认 | 不能给不存在或不知情的账户充值（防员工用假充值套赠送金） |

确认收款时：

- 一个事务里：充值单改“已付款”→ 记一张充值凭证（第 7 节）→ 附送的券发到顾客账户 → 现金进钱箱 / 扫码进“待核款”。
- 收款方式是扫码时，跟现在一样在“核款”页对账。
- 权限：新权限 `stored.topup`（店主、经理、接单员默认都有，因为是收银动作）。单笔超过额度（默认 5000.00）要经理授权码。
- **撤销充值**：只有当天、余额一分没动、店主或经理授权码，记反向凭证，钱箱出钱。动过的只能走“退储值”（第 8.3 节）。

## 7. 账怎么记

### 7.1 新账户种类（同一张 `wallet_accounts`）

| `kind` | 归属 | 余额 | 说明 |
|---|---|---|---|
| `stored_principal` | 顾客 + 门店 | ≥ 0 | 储值本金 |
| `stored_bonus` | 顾客 + 门店 | ≥ 0 | 储值赠送金 |
| `store_topup` | 门店 | 可负 | 门店收到的充值本金（负 = 预收） |
| `store_bonus` | 门店 | 可负 | 门店送出的赠送金（负 = 营销支出） |
| `store_stored_sales` | 门店 | 可正 | 顾客用储值付的钱 |

现有的 `store_credit / store_refund / store_sales` 不动。

### 7.2 凭证（单位：分）

| 业务 | 明细 |
|---|---|
| 顾客充 1000 送 200 | `store_topup` −100000，`stored_principal` +100000；`store_bonus` −20000，`stored_bonus` +20000 |
| 用储值付 300（按比例 250 + 50） | `stored_principal` −25000，`stored_bonus` −5000，`store_stored_sales` +30000 |
| 订单取消 / 金额变小退回 | 反向凭证，本金、赠送按原比例退回（第 8.2 节） |
| 撤销充值 | 充值凭证的反向凭证 |
| 退储值（顾客原因） | 见 8.3 节样例 |

## 8. 金额规则

### 8.1 用储值付款

- 结算页、扫码堂食结账、代客单（短信验证码）都能用，入口和店铺余额一样。
- 顾客看到一行“**本店余额 可用 1,250.00**”（退款余额 + 储值合计，点开看分项），开关默认开（Q6）。
- 扣款顺序：**先用退款余额，再用储值**（退款余额本来就是顾客已付的钱，先用掉对顾客最有利，也让退现金的那部分本金留在后面）。
- 储值内部**按比例**扣（Q2）：

```
储值这次要扣 x，扣之前本金 P、赠送 B：
  赠送份 = floor(x × B / (P + B))
  本金份 = x − 赠送份
```

赠送份向下取整，零头落在本金上——顾客多用一分本金、少用一分赠送，剩下可退的本金少一分不多一分。

- 金额都由服务器在下单事务里算，前端只传“用不用”；锁账户行、条件更新、`CHECK` 兜底（和店铺余额同样的并发防护）。

### 8.2 订单金额变了、订单退款

- **金额变小**（退菜、打折、取消）：先减还没收的现金；还不够，把多出的部分按这张单用掉的比例退回退款余额、储值本金、储值赠送三份（本金份、退款余额份向下取整，零头算赠送，每份不超过这张单用掉的）。（2026-11-27 brian 定：顾客看到的“现金余额”=本金+退款余额、“充值赠送金”=赠送，两者都按消费比例退回；原来是先退储值、最后退退款余额。）
- **订单退款**（按菜退款）：一张单的实付分四份——现金、退款余额、储值本金、储值赠送。按“累计目标”分开：

```
本次退款 r，之前已退累计 R，订单实付 T；每一份原付 Ck、已退 Ckr：
  现金份   = floor((R + r) × C现金 / T) − C现金r
  本金份   = floor((R + r) × C本金 / T) − C本金r
  退款余额份 = floor((R + r) × C余额 / T) − C余额r
  赠送份   = r − 上面三份
```

零头都落在赠送金上：可退现金的两份（现金、本金）永远不会多一分。全部退完时每一份正好退回原数。

- 储值付的部分**只能退回储值**（本金回本金、赠送回赠送）；现金份照现有规则可以退现金或退到店铺余额。

### 8.3 退储值（顾客要把储值退成现金）

只在商家后台，由店主或经理操作（权限 `stored.cashout`，超过 2000.00 要店主授权码），顾客当面或电话确认。按 Q3 推荐：

| 原因 | 退给顾客 | 赠送金 |
|---|---|---|
| 顾客原因（不想用了、搬走） | 剩余本金 − 已用赠送（不低于 0） | 剩余全部作废 |
| 门店原因（停业、搬店、服务问题） | 剩余本金全退 | 剩余全部作废 |

“已用赠送” = 这个顾客在本店所有充值送出的赠送 − 现在剩下的赠送 − 已作废的赠送。退完本金、赠送都变 0。退现金从钱箱出，对账单列。

### 8.4 和计价引擎的关系

储值和店铺余额一样**不是** `Adjustment`，不进 `order_discounts`，不改满减门槛、券、服务费、税、抹零。`loadMoney → choosePromo → priceMoney → saveMoney` 不变；储值的扣、退在 `saveMoney` 之后同一事务里，由 `settleTenders` 扩展处理。R1–R3 重放规则不受影响。

### 8.5 营业额和税（Q8）

- 充值时：不是营业额，是预收款（负债）。对账页“储值充值”单列，不进营业额。
- 用储值付款时：订单金额照常算营业额，税照订单已算的税（引擎不变）。
- 账单另列“**储值赠送抵扣**”（用掉的赠送金合计），这是门店的营销成本；“储值本金收款”和现金一样是真收入。
- 各国对礼品卡/预收款的增值税时点不同（例如在兑换时还是收款时计税），本方案按“兑换时计税”的常见做法出报表，**请商家的会计确认**。

## 9. 安全、风控和停业

| # | 风险 | 防御 |
|---|---|---|
| 1 | 店员记了充值但没收钱（套赠送金） | 充值现金进钱箱，对账少钱一眼看到；店员发起的充值要顾客短信验证码；单笔大额要授权码；每员工每天充值合计在报表里可查 |
| 2 | 店员给自己或亲友账户充值，用店里的钱 | 同上：没有真钱进钱箱就对不上账；撤销只能当天、余额没动、授权码 |
| 3 | 充值后马上退储值套赠送 | 顾客原因退款扣回已用赠送，赠送作废；退储值要店主/经理权限和授权码 |
| 4 | 用储值买单再退现金 | 储值付的只能退回储值（W14） |
| 5 | 重复确认收款（双击、两个店员同时扫码） | 充值单状态锁 + 幂等键；同一充值单只能确认一次 |
| 6 | 改包：改档位金额、改赠送 | 前端只传档位 id；入账按服务器上的档位快照；过期或停用的活动拒绝 |
| 7 | 活动限次被绕过（多个手机号） | 按顾客账户限次；首充专享按“这个顾客在本店有没有过充值”；同一设备/同一付款人的异常提醒店主（第二批） |
| 8 | 门店收了一堆储值然后停业 | 平台显示每家门店“欠顾客储值”，超过阈值提醒平台运营；门店有储值不能删除（已有 `CREDIT_OWED` 逻辑扩展）；停业时平台冻结，按 8.3“门店原因”处理，每笔有记录 |
| 9 | 顾客账号被盗花储值 | 登录短信验证码；每笔储值变动站内消息；余额不能转出提现；平台可冻结 |
| 10 | 四舍五入多退本金 | 整数分；累计目标；可退现金的份永远向下取整 |

平台后台（第三批）：国家开关和余额上限、每家门店储值概况（欠顾客多少、本月充值/消费/退）、冻结、导出。

## 11. 金额验算（PRICING_CHECK 要加什么）

计价引擎不变，C 规则不变。新增：

| 编号 | 规则 |
|---|---|
| W8 | 储值本金、赠送两个账户各自 ≥ 0；每张充值凭证：本金 = 充值单实收，赠送 = 充值单档位快照；已付款的充值单和充值凭证一一对应 |
| W9 | 每次储值消费：赠送份 = floor(x × B / (P+B))（P、B 为扣之前），本金份 = x − 赠送份 |
| W10 | 每张单：`credit_paid + stored_principal_paid + stored_bonus_paid ≤ total`（任何时候）；取消的单三项都 = 0；先用退款余额再用储值 |
| W11 | 每张单的两列 = 该单储值消费凭证 − 退回凭证（分本金、赠送分别相等） |
| W12 | 订单退款四份按累计目标拆，现金、本金、退款余额三份向下取整；每份累计退款 ≤ 原付，全部退完各自相等 |
| W13 | 储值付的退款只回储值（本金回本金、赠送回赠送）；退现金/转账 ≤ 现金实付 |
| W14 | 退储值：顾客原因退现金 = max(0, 剩余本金 − 已用赠送)，门店原因 = 剩余本金；之后本金、赠送都 = 0 |
| W15 | 每个门店：所有顾客 `stored_principal + stored_bonus` 之和 = −(`store_topup` + `store_bonus` + `store_stored_sales`)（例：充 1000 送 200 用掉 300 → 900 = −(−1000 − 200 + 300)）；对账钱箱里的储值现金 = 现金充值 − 撤销 − 退储值现金 |

### 手算样例（实现时加进 `TestPricingCheckSamples` 和 PRICING_CHECK.md 第 4 节）

**SV-S1 充值和按比例消费**

充 1000.00 送 200.00 → 本金 1000.00、赠送 200.00。下单用储值 300.00：
- 赠送份 = floor(30000 × 20000 / 120000) = floor(5000) = 5000 → 50.00
- 本金份 = 300.00 − 50.00 = 250.00
- 剩：本金 750.00、赠送 150.00（比例还是 5 : 1）

**SV-S2 除不尽**

本金 1000.00、赠送 150.00，用储值 99.99：
- 赠送份 = floor(9999 × 15000 / 115000) = floor(149985000 / 115000) = floor(1304.217…) = 1304 → 13.04
- 本金份 = 9999 − 1304 = 8695 → 86.95
- 剩：本金 913.05、赠送 136.96

**SV-S3 储值付的单分两次退款**

订单实付 300.00 = 本金 250.00 + 赠送 50.00。先退 100.00：
- 本金份 = floor(10000 × 25000 / 30000) = floor(8333.33) = 8333 → 83.33；赠送份 = 100.00 − 83.33 = 16.67

再退剩下 200.00（累计 300.00）：
- 本金份 = floor(30000 × 25000 / 30000) − 8333 = 25000 − 8333 = 16667 → 166.67；赠送份 = 200.00 − 166.67 = 33.33

合计：本金 83.33 + 166.67 = 250.00，赠送 16.67 + 33.33 = 50.00，各自正好退回。

**SV-S4 四种付款混合，除不尽**

订单实付 500.00 = 现金 100.00 + 退款余额 100.00 + 储值本金 250.00 + 储值赠送 50.00。第一次退 99.99：
- 现金 = floor(9999 × 10000 / 50000) = floor(1999.8) = 1999 → 19.99
- 本金 = floor(9999 × 25000 / 50000) = floor(4999.5) = 4999 → 49.99
- 退款余额 = floor(9999 × 10000 / 50000) = 1999 → 19.99
- 赠送 = 9999 − 1999 − 4999 − 1999 = 1002 → 10.02（精确值 9.999，零头落在赠送）

第二次退剩下 400.01（累计 500.00）：
- 现金 = 10000 − 1999 = 8001 → 80.01；本金 = 25000 − 4999 = 20001 → 200.01；退款余额 = 10000 − 1999 = 8001 → 80.01
- 赠送 = 40001 − 8001 − 20001 − 8001 = 3998 → 39.98

合计：现金 100.00、本金 250.00、退款余额 100.00、赠送 10.02 + 39.98 = 50.00，各自正好。

**SV-S5 退储值**

充 1000.00 送 200.00，用了 300.00（本金 250.00 + 赠送 50.00），剩本金 750.00、赠送 150.00：
- 顾客原因：已用赠送 = 200.00 − 150.00 = 50.00；退现金 = 750.00 − 50.00 = **700.00**；赠送 150.00 作废。
- 门店原因：退现金 = **750.00**；赠送 150.00 作废。

**SV-S6 已用赠送比剩余本金多**

充 100.00 送 100.00，用了 180.00（赠送份 = floor(18000 × 10000 / 20000) = 9000 → 90.00，本金 90.00），剩本金 10.00、赠送 10.00：
- 顾客原因：退现金 = max(0, 10.00 − 90.00) = **0.00**；本金 10.00 和赠送 10.00 都清零（本金 10.00 记为扣回）。
- 门店原因：退现金 = **10.00**。

**SV-S7 订单金额变小，先减现金，再按比例退回三份**（2026-11-27 改）

订单 200.00，用退款余额 50.00、储值 120.00（本金 100.00 + 赠送 20.00），到付 30.00（还没收）。退菜后订单变 110.00（少 90.00）：
- 到付 30.00 → 0，还差 60.00
- 退回 60.00，按这张单用掉的 170.00 拆：本金 = floor(6000 × 10000 / 17000) = floor(3529.41) = 3529 → 35.29；退款余额 = floor(6000 × 5000 / 17000) = floor(1764.70) = 1764 → 17.64；赠送 = 6000 − 3529 − 1764 = 707 → 7.07
- 顾客看到：现金余额退回 35.29 + 17.64 = 52.93，赠送金退回 7.07（按 150 : 20 的精确值是 52.94 : 7.06，现金那边向下取整）
- 结果：订单 110.00 = 退款余额 32.36 + 本金 64.71 + 赠送 12.93 + 现金 0；W10 成立。

## 13. 需要你决定的问题

| # | 问题 | 选项 | 推荐 |
|---|---|---|---|
| Q1 | 充值送什么？ | A. 只送赠送金<br>B. 只送优惠券<br>C. **每档送赠送金，也可以再附一张券（商家选）** | **C**。券的系统已经有了，附送券能拉回头客（例如“充 1000 送 100 + 下次满 300 减 30 券”） |
| Q2 | 消费时本金和赠送先扣谁？ | A. **按比例扣**<br>B. 先扣本金，再扣赠送<br>C. 先扣赠送，再扣本金 | **A**。账最清楚，每一单的营销成本算得出；退储值时公平；B 对顾客不利，C 对商家不利 |
| Q3 | 储值能不能退现金？ | A. **能退剩余本金：顾客原因扣回已用赠送，门店原因全退；赠送金作废，不退现金**<br>B. 一律不退<br>C. 能退剩余本金，不扣回已用赠送 | **A**。和法院判例的思路一致；B 容易被投诉、在一些地方条款无效；C 会被“充值—花赠送—退本金”套利 |
| Q4 | 会不会过期？ | A. **本金、赠送都不过期**<br>B. 本金不过期，赠送金商家可设有效期（按每笔充值单独算到期） | **A**（首版）。菲律宾法律禁止储值过期；赠送设有效期要按每笔充值分批记账，复杂度翻倍，以后需要再加 |
