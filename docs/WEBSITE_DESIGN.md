## 1. 要做什么

给这套点餐系统做一个**对外介绍产品的企业官网**，读者是想用这套系统的**餐厅老板和连锁品牌**（不是点外卖的顾客）。官网要做到四件事：

1. 十秒内让老板明白“这是什么、能帮我什么”：一套系统同时管外卖、自取、堂食和代客下单。
2. 用真实界面截图把主要功能讲清楚，让老板能对上自己店里的场景。
3. 把感兴趣的人变成**线索**：填一张表（预约演示 / 申请入驻），直接进平台后台现有的“顾客服务 → 入驻申请”，由我们跟进。
4. 搜索引擎和多语言：在目标国家用本地语言能搜到。

不在这次范围：线上签约付款、商家自助开通门店（现在开店仍由平台在后台手动建，见 `docs/ADMIN_DESIGN.md`）、博客内容运营。

## 2. 调研：同类官网怎么做

| 官网 | 结构上值得学的 | 不学的 |
|---|---|---|
| Toast（美国） | 每页顶部和底部都有“预约演示”按钮；产品按“硬件 / 软件 / 集成”分组；按餐厅类型（快餐、正餐、酒吧、咖啡）分解决方案页；价格页给起价、细节放脚注；演示表单只要姓名、电话、店名 | 页面太多、产品线太长，我们现阶段撑不起 |
| Square for Restaurants | 价格页三档（免费 / Plus / Premium），按国家显示本地币种和价格；每档可试用 30 天；按场景分页（快餐、正餐、酒吧） | 硬件销售部分 |
| StoreHub（东南亚） | 每个国家一个子站（`/my/`、`/ph/`），本地案例、本地支付方式；价格页按年付送月数；F&B 单独落地页 | — |
| Eats365（东南亚、香港） | 多国多语言；强调多门店连锁管理；大量“XX 国最好的 POS”SEO 文章带流量 | 靠大量 SEO 软文，前期不做 |
| 客如云、美团收银、哗啦啦（国内） | 首页按“业态”入口（正餐、快餐、茶饮、烘焙）；突出“一体化”（收银 + 外卖 + 会员 + 营销）；大量门店 logo 和数据做背书；“免费试用 / 预约演示”常驻右侧浮窗 | 面向国内市场和微信生态，和我们的东南亚多语言市场不同 |

**共同的套路**（我们照着做）：

- 首页结构固定为：大标题 + 截图 → 痛点/卖点 → 功能分块 → 适用业态 → 数字和客户背书 → 常见问题 → 底部再放一次表单入口。
- 主按钮只有一个动作：“预约演示”或“免费试用”。登录入口放右上角小链接，给老客户用。
- 截图用真实产品界面，放在手机、平板、电脑的外框里。
- 每个国家/语言一个 URL（`/en/`、`/zh/`），方便搜索引擎收录。

## 3. 我们的卖点（从现有功能里提炼）

现有系统已经做完的功能，按老板关心的顺序归成 6 组，官网所有页面都围绕这 6 组写：

| 卖点 | 对应现有功能 | 设计文档 |
|---|---|---|
| **一套系统接所有订单** | 外卖商城（按位置列店、配送费起送价）、顾客自取、堂食桌台扫码点餐、代客下单（微信/电话来的单，看图点菜、会员号）、加单 | MALL / DINE_IN_ORDER / MANUAL_ORDER / ADD_ON_ORDER |
| **后厨不乱** | 按制作台分单、烹饪进度看板、催菜、出餐目标时间、退菜和损耗授权 | COOKING_PROGRESS / VOID_ITEM |
| **菜单好管** | 分类、规格、口味模板、加料模板、Excel 批量导入导出、菜品多图、按堂食/外卖/自取上架 | NOTE_TEMPLATE / menu-import / topping-templates |
| **生意做得多** | 满减、指定菜品打折、第二份半价、复购优惠券、宣传物料轮播、会员和地址库、送餐热力图 | COUPON / PRICING_REVIEW / DELIVERY_ADDRESS_STATS |
| **钱算得清** | 统一计价引擎、结账打折/抹零/改实收、多种付款方式、退款、对账页、金额流水、按店铺国家自动币种 | CHECKOUT_DISCOUNT / PRICING_CHECK |
| **人管得住** | 店主/经理/接单员角色权限、员工工作台 App（安卓/iOS）、骑手接单导航、考勤和工作汇总、顾客和商家聊天、平台客服 | STAFF_ACCESS / RIDER_APP / STAFF_REPORT / CHAT |
| **跨国多语言**（贯穿全部） | 12 种界面语言、菜单自动翻译、阿拉伯语从右到左、缅文 Zawgyi 自动转换、按国家定币种和电话区号 | I18N |

一句话定位（推荐）：**“一套系统，管好外卖、自取、堂食和代客下单。”**
英文：*One system for delivery, pickup, dine-in and phone orders.*

和竞品比，我们讲得出口的差异：
1. **不抽佣**：自己的外卖商城和店铺页，顾客直接向店里下单（对比外卖平台 20–30% 佣金）。
2. **代客下单**：东南亚华人餐厅大量订单来自微信、电话，现成系统很少专门做。
3. **12 种语言 + 缅文/高棉文/阿拉伯文**：竞品很少覆盖到缅甸、柬埔寨。
4. **员工 App 一账号多身份**：后厨岗位和骑手同一个 App。

## 6. 视觉风格

**沿用顾客端的深红米金品牌色和七宝纹**，让官网、商城、点餐页看起来是一家：

| 用途 | 颜色 | 来自 |
|---|---|---|
| 主色（按钮、标题强调） | 深红 `#a02c20`，深一级 `#8f251b` | `web/src/styles.css` 的 `.warm` |
| 点缀（数字、标签、图标） | 金 `#f4cf73`，浅金 `#fbe7b3` | 同上 |
| 页面底色 | 米色 `#f8efe1`，卡片 `#fffaf2` | 同上 |
| 正文 | 深棕 `#3b1f14`，辅助 `#7b6657` | 同上 |
| 纹样 | 金色七宝纹（同 `--motif`），只用在首屏、底部表单、价格推荐档这些红色大块上，淡出不铺满 | 同上 |

- 版式：最大宽度 1200px，大标题 48/40px（手机 30px），正文 17px（手机 16px），留白大，每屏一个重点。
- 字体：系统字体栈（中文苹方/思源黑体，泰缅高棉阿拉伯用对应 Noto 字体），不加载大字体文件，和系统一致（`web/src/fonts.ts`）。
- 图片：真实截图放进设备外框（电脑、平板、手机），配少量餐饮实拍（菜品图可用系统里的演示菜品图）。不用通用插画。
- 按钮：主按钮实心深红白字、次按钮白底红框，和顾客端规则一致。
- 不照搬任何竞品或外卖平台的品牌和配色（MALL_DESIGN 已定的规则）。
- 适配：PC / iPad / 手机三档，和系统一样用 1440 / 820 / 390 宽度检查；阿拉伯语页面整体从右到左。

## 7. 技术选型

### 7.1 独立静态站还是放进现有项目？

| 方案 | 好处 | 坏处 |
|---|---|---|
| A. 放进现有 Vue 前端（`web/` 加路由） | 少一个项目 | 现有前端是单页应用，搜索引擎抓取差；商城已经占了 `/`；官网改文案要跟着整套系统发版 |
| **B. 同一个仓库里新建 `site/`，用 Astro 生成静态页（推荐）** | 每页是现成 HTML，SEO 最好、打开快；可以复用 `web/` 的颜色、七宝纹、语言表；文案改动单独发版；和系统同仓库，表单接口一起改 | 多一个构建步骤 |
| C. WordPress 等建站工具 | 非技术人员能改 | 要另维护一套 PHP 和数据库，安全补丁多，风格难统一 |

**推荐 B**：仓库加 `site/` 目录，Astro（输出纯静态 HTML，可以直接写 Vue 组件做语言切换、表单这类交互小块），构建产物是一堆 `.html` + 图片，不需要服务器运行时。

### 7.2 多语言

- URL 带语言前缀：`/zh/…`、`/en/…`；每页 `<link rel="alternate" hreflang>` 互相指向，`x-default` 指向英文。
- 根路径 `/`：Caddy 按浏览器 `Accept-Language` 跳到对应语言（搜索引擎不带这个头，落到英文）；用户手动切换后记在 cookie `lang`，和系统共用同一个 cookie 名，进系统后语言一致。
- 语言代码和名字复用 `web/src/langs.ts`（12 种），官网先开其中几种（第 12 节问题 3）。
- 文案放 `site/src/content/{lang}/*.md` / `*.json`，一个语言一个文件夹。营销文案**人工翻译**（可先用系统的自动翻译出草稿，再找母语者改）；截图按语言自动生成。
- 阿拉伯语 `dir="rtl"`，泰缅高棉加大行高，沿用系统的做法。

### 7.3 SEO 和性能

- 每页独立 `<title>`、`description`、Open Graph 分享图（每页一张，自动生成带品牌色的卡片）。
- `sitemap.xml`（含各语言）、`robots.txt`、规范链接 `canonical`。
- 结构化数据：`Organization`、`SoftwareApplication`（含价格区间，若公开）、`FAQPage`。
- 图片转 WebP/AVIF、懒加载，首屏图预加载；页面 JS 只在表单和语言切换处加载，目标 Lighthouse 性能分 ≥ 95。
- 官网**不加载谷歌地图**（成本和速度），表单城市用文本框；入驻审核时平台再在后台补地图位置。
- 上线后在 Google Search Console 提交站点地图；统计用自建 Umami（不用 Cookie，不需要弹同意横幅），或 GA4（第 12 节问题 6）。

### 7.4 自动截图

加一个脚本 `e2e/site-shots.cjs`：用演示数据（`cmd/seed`）启动系统，按语言、按设备尺寸自动截官网要用的界面图，输出到 `site/public/shots/{lang}/`。系统界面改版后重跑一次，官网图片就是最新的；每种语言的截图也是这种语言的界面。

## 8. 表单怎么接现有入驻审核

现状：顾客在“我的 → 申请入驻”提交（`POST /api/v1/customer/applications`，要求顾客先登录，地图选址），存到 `merchant_applications` 表，平台后台“顾客服务 → 入驻申请”里看、批准或拒绝；批准后由平台手动建商户。

官网访客没有顾客账号，也不该要求先短信登录。做法：**同一张表、同一个审核页（AdminCustomers.vue 的“入驻申请”标签），加一个免登录的公开入口**。

### 8.1 后端

1. 迁移：`merchant_applications` 
   - `customer_id` 改为可空（官网来的没有顾客）；
   - 加 `source TEXT NOT NULL DEFAULT 'app' CHECK (source IN ('app','website'))`；
   - 加官网字段：`store_type`、`store_count`、`wants TEXT[]`（外卖/自取/堂食/代客下单）、`im_kind`、`im_handle`、`email`、`lang`、`referrer`、`utm`（JSONB）；
   - 加跟进状态 `follow_up`（待联系 / 已联系 / 已演示 / 无效），和现有 `status`（待审核 / 批准 / 拒绝）分开，批准仍是“可以开店”的意思。
2. 新接口 `POST /api/v1/public/leads`（免登录）：校验字段，写入 `source='website'`，返回编号。
3. 防刷：
   - 用现有的按 IP 限流（`publicWrites` 同类的 limiter，比如每 IP 每小时 5 次）；
   - 隐藏字段蜜罐 + 最短填写时间（打开页面不到 3 秒就提交的丢弃）；
   - 同一手机号 24 小时内重复提交只更新不新增；
   - 可选 Cloudflare Turnstile 人机验证：密钥放平台后台“密钥设置”页（已有），没填就不启用。
   - **不发短信验证码**（省钱，减少流失）；电话真假由跟进时判断。
4. 通知：新线索进平台后台时，总览页和“顾客服务”菜单显示数字角标；另外可选推到平台客服收件箱（OpenIM，已有），值班管理员手机上就能看到。邮件系统目前没有，不为这个新加。

### 8.2 平台后台“顾客服务 → 入驻申请”标签页

- 列表加“来源”标签（App / 官网）和筛选；官网来的显示店铺类型、门店数、想用的功能、联系方式（WhatsApp/Telegram 可点击直接打开）。
- 加“跟进状态”下拉和一条备注；
- 现有“批准 / 拒绝”不变。官网来的没有顾客账号，所以批准后不发站内消息，改为提示管理员“请通过 xx 联系对方”。

### 8.3 跨域

官网和系统是不同域名。推荐在官网域名下用 Caddy 把 `/api/v1/public/leads` 转发到系统 API（同源，不需要 CORS，也不暴露系统域名）。系统 API 只对这一条接口按 `X-Forwarded-For` 限流，沿用现有真实 IP 的规则（`deploy/nginx.conf`）。

## 9. 域名和部署

### 9.1 域名

商城已经占用系统域名的 `/`，所以官网单独用一个域名：

| 域名 | 用途 |
|---|---|
| `brand.com`（官网，推荐用主域名） | 企业官网 |
| `order.brand.com`（或现有系统域名） | 外卖商城 + 商家后台 + 员工工作台 + API |
| `demo.brand.com`（第三批，可选） | 演示环境，每晚重置演示数据，给潜在客户自己点着试 |

### 9.2 部署（推荐和系统同一台服务器）

```
浏览器 ──HTTPS──> Caddy（已有）
   ├─ brand.com          → site 容器（Nginx 静态文件）
   │     └─ /api/v1/public/leads → web 容器 → api
   └─ order.brand.com    → web 容器（现有，不变）
```

- 新增 `Dockerfile.site`：Node 构建 Astro → Nginx 静态镜像，`docker-compose.yml` 加 `site` 服务；Caddyfile 加一个站点块。`docs/DEPLOY.md` 加一节。
- 官网是纯静态，以后也可以不改代码搬到 Cloudflare Pages（免费、全球 CDN），只需把表单那条接口指回系统域名。
- CI：`site/` 有改动时跑构建、死链检查、Lighthouse 基础检查。
