# Claude 开发入口

目标是把海外华人餐厅的点餐和外卖设计落实成可运行、可验证的系统。第一批交付先跑通堂食，随后依任务清单完成自营外卖、运营能力和获准的外部接入。

## 开始之前

1. 阅读 [Gin 开发设计](docs/Restaurant_Gin_Development_Design_v1.0.md) 和 [实施任务](IMPLEMENTATION_TASKS.md)，核对工作区内现有代码、约定和未提交改动。有现有实现时优先在原有结构上补齐功能。
2. 当前技术与部署决策以 Gin 方案为准。产品行为以[功能设计](docs/Restaurant_Functional_Design_v1.0.md)及[逐页说明](docs/page-design/README.md)为准。查看 [UI 索引](ui/README.md)对照视觉和模板。图片里的订单、价格和数据均为演示示例，服务端按真实门店配置计算。
3. 从第一个未完成且可验证的阶段动手。先建立可本地运行的工程和可重复的数据库迁移，再把前端、Gin API 与真实 PostgreSQL 串成首个业务闭环。方案中的接口和表名可随仓库约定调整，业务语义、权限和验收行为须满足设计。

## 首版技术决策

- Go + Gin，按业务模块组织，REST 接口用 OpenAPI 3.1 描述。领域和应用逻辑使用 Go 类型与 `context.Context`，供 API、Worker 和测试复用。
- PostgreSQL + `pgx/v5` + sqlc + Goose。API 与后台 Worker 共用 Go 模块和镜像。生产使用 HTTPS、Nginx、Docker Compose，优先托管 PostgreSQL。
- Vue 3 + TypeScript + Vite。商家后台用 Element Plus。顾客 H5、iPad、后厨及骑手适配主要设备，默认简体中文。
- REST 执行业务命令，SSE 通知页面刷新。连接恢复后重新获取授权范围内的快照。
- 试点按联网营业、柜台收款和到付设计。线上收款、GrabFood 和 foodpanda 分渠道开通；缺少正式授权时，用本地测试数据验证接口边界和重试，自营链路继续开发。

## 业务规则

- 所有订单、门店配置、工作台和推送按商户／门店与岗位隔离。骑手只可操作当前指派，堂食顾客只可访问有效桌次。
- 扫码和 iPad 共享该桌已提交账单。每次加菜生成独立批次。关台后旧桌次凭证失效。报价、菜品规格、金额和活动保存快照。
- 接单、加菜和派发制作任务在相应的数据库事务中处理。重复请求沿用同一幂等键并读取原结果。并发修改按版本及当前状态重新校验。
- 每个制作项归一个有效工作台；套餐按子项分派。需制作但未分台的菜保留在总览并影响齐菜判定。配置变更影响新派发，在制任务的改派有操作记录。
- 打包台按整单核对菜品、清单版本和袋数。完成打包、实际交接、送达、骑手代收和门店核款分别记录。
- 各入口的模板、主题配置与菜单规则分开。每套模板复用相同的报价、权限、下单和订单状态逻辑。

## 每阶段交付

提供实际代码与迁移、可重复运行的演示数据、本地启动命令、针对变更的测试与实测结果，以及仍需门店或第三方确认的事项。环境变量用示例文件说明，开发演示使用测试账号和凭证。涉及生产授权时，先在测试环境核对合作方能力。
