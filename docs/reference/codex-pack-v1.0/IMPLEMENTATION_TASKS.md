# 实施任务与验收

按可运行的业务闭环推进。需求细节见 [Gin 开发设计](docs/Restaurant_Gin_Development_Design_v1.0.md)、[完整功能设计](docs/Restaurant_Functional_Design_v1.0.md)和 [UI 效果图索引](ui/README.md)。

## 阶段 0 · 工程与真机验证

| 任务 | 实作内容 | 完成条件 |
|---|---|---|
| 0.1 本地工程 | 建立 Go API、Worker、PostgreSQL 迁移、Vue 入口、Compose、环境变量示例、开发数据与启动说明。 | 从干净开发库可执行迁移、启动服务、打开页面并查看健康状态。 |
| 0.2 登录与授权 | 商户、门店、员工岗位、设备及访客权限骨架。实现共享错误结构和请求跟踪。 | 至少两家商户的样例数据可验证读写和订阅隔离。 |
| 0.3 接口与实时骨架 | 建立 OpenAPI 契约。接通同源代理、SSE 心跳、重连与快照。 | 浏览器连接后可看到真实数据库变更。重启 API 能重连并获取最新状态。 |

## 阶段 1 · 堂食首个完整闭环

| 任务 | 实作内容 | 完成条件 |
|---|---|---|
| 1.1 店铺与菜单 | 门店、桌位、草稿和生效菜单、菜品规格、套餐子项、基础模板。 | 已发布菜单可访问；草稿内容留在后台。 |
| 1.2 桌次、扫码和 iPad | 开台、桌码兑换、设备配对、报价、提交与加菜。 | 手机和 iPad 各提交一批，店员看到同一桌次账单和独立批次。重复提交只生成一批。 |
| 1.3 工作台与出餐 | 创建制作台、分配菜品、保存任务归属、总览、指定工位与出餐动作。 | 炸台只收到炸物，饮品台只收到饮品。无工作台的制作项有提示。停用工位的旧任务仍能处理。 |
| 1.4 开单与关台 | 店员开单、修改草稿、送厨后仅追加新批次、记录实收、关台。 | 柜台结算时使用最新账单。并发关台与加菜不会重复入账，旧桌次访问失效。 |

首个演示用同一门店的 08 桌。手机点炸物，iPad 加饮料，炸台和饮品台各确认备好，出餐岗位确认上桌，柜台结账关台。下一桌扫码只进入新的桌次。再模拟加菜确认前网络断开，验证原幂等键能查回结果。

## 阶段 2 · 自营外卖、自取与收款

| 任务 | 实作内容 | 完成条件 |
|---|---|---|
| 2.1 顾客链接与报价 | 公开门店 URL、购物车、收餐地址、配送区、外卖／自取及顾客订单进度。 | 更换地址后展示新费用，顾客确认后才出单。配送超范围保留购物车并提示可用服务。 |
| 2.2 接单、打包与交接 | 接拒单、送厨、独立打包台、袋数核对、实际交接和自取。 | 缺一项时无法确认打包。已打包未交接的单如有改菜，旧清单失效。实际交接只推进一次。 |
| 2.3 骑手与核款 | 门店指派和改派、骑手取餐、到达、送达、异常和到付处理。 | 已送达和现金核款可独立查询。重复送达不多记代收，被改派的骑手无法写回。 |

## 阶段 3 · 商家运营

- 完成外卖、扫码、iPad 各入口的多套模板、预览和独立发布。切换模板后菜单、购物车与下单流程继续按原有规则运行。
- 完成 Excel 上传、异步解析、行级错误、确认写草稿、菜单发布。用至少一份同时含有效行和错误行的测试表验收。
- 完成活动创建、试算、发布、暂停和用量展示。验证门店当地时间跨午夜、名额并发、已确认单的历史优惠，以及回调或取消引起的用量变化。

## 阶段 4 · 获准的外部接入

- 按门店能力开启线上支付、GrabFood 或 foodpanda，保留外部和内部状态，使用任务表做重试、补查和对账。
- 使用测试环境覆盖验签、重复、事件乱序、迟到付款、退款和漏单补查。真实门店上线按合作方授权范围处理。

## 发布前统一验收

| 类别 | 检查 |
|---|---|
| 数据一致性 | 真实 PostgreSQL 验证重复提交、售罄变更、活动名额冲突、关台加菜并发、打包清单并发及代收去重。 |
| 数据权限 | 跨商户、跨门店、已关桌次、设备解绑、骑手改派和文件／SSE 越权均覆盖。 |
| 终端体验 | 手机扫码、iPad 真机、商家工作台、后厨工位、打包台和骑手 H5 跑通。检查断网、重连、挂屏、唤醒与中文长文案。 |
| 恢复能力 | 模拟 API 重启、Worker 租约到期、数据库恢复和回调迟到。验证已确认单可查、工作台恢复、任务可重试。 |
| 交付记录 | 更新启动方式、迁移方式、演示账号或测试数据加载方式、回归步骤，以及需要业务方确认的前提。 |
